# Лабораторная работа 4

Система управления студентами общежития. Frontend: Vue 3, JavaScript, Vue Router, Pinia и RxJS. Backend: Spring Boot, jOOQ и PostgreSQL.

## Запуск

1. Установить и запустить Docker Desktop с Linux-контейнерами.
2. Открыть терминал в папке `lab4`.
3. При первом запуске на другом компьютере скопировать `.env.example` в `.env` и заполнить пароли и `JWT_SECRET`. Секрет должен содержать минимум 32 ASCII-символа (32 байта UTF-8). На текущем ноутбуке `.env` уже создан.
4. Выполнить:

```sh
docker compose up --build
```

Открыть http://localhost:8080. Порт можно изменить через `HTTP_PORT` в `.env`. Swagger находится по адресу http://localhost:8080/swagger-ui/index.html.

Первый запуск скачивает образы и зависимости. Дождаться запуска всех трех сервисов. Java, Node.js и PostgreSQL отдельно устанавливать для этого запуска не нужно.

Администратор создается при первом запуске из `ADMIN_USERNAME`, `ADMIN_EMAIL` и `ADMIN_PASSWORD` в `.env`. Регистрация через интерфейс создает только USER. Пароли и `.env` не добавляются в git.

## Запуск через Docker Desktop

Первую сборку выполняют командой `docker compose up --build` из папки `lab4`: это требование письменного задания. После создания контейнеров в Docker Desktop на вкладке Containers появляется группа Compose `lab4`.

Для обычного показа открыть Docker Desktop, найти группу `lab4` и нажать Start. Для остановки использовать Stop у этой же группы. Затем открыть http://localhost:8080 и дождаться готовности приложения. Группу необходимо один раз создать указанной командой; на другом ноутбуке одного запуска Docker Desktop недостаточно. Если изменились исходники, повторить сборку через Compose.

Этот порядок добавлен по устному уточнению преподавателя. 9 ноября 2026 года остановка и повторный запуск трех сервисов кнопками Docker Desktop проверены на отдельной тестовой группе Compose.

## Остановка и данные

Остановить приложение: `Ctrl+C`, затем:

```sh
docker compose down
```

Данные PostgreSQL сохраняются в Docker volume `postgres_data`. Следующий запуск использует ту же базу. При первом запуске Flyway создает таблицы и добавляет учебных студентов. Установленная в Windows база лабы 3 не используется.

## Структура

- `frontend/`: Vue-приложение, сборка Vite и конфигурация Nginx.
- `backend/`: копия Java-бэкенда лабы 3 с дополнениями для лабы 4.
- `bruno/`: коллекция API-запросов.
- `docker-compose.yml`: совместный запуск базы, backend и frontend.
- `.env.example`: пример конфигурации.

Compose читает `.env` из корня `lab4`. Файл `backend/.env.example` нужен только при отдельном запуске backend через Gradle.

Оба Dockerfile используют многоэтапную сборку. Nginx раздает собранные файлы Vue и передает `/api/` в backend. Остальные адреса страниц возвращают `index.html`, после чего маршрут выбирает Vue Router. Backend ожидает готовности базы, а Nginx ожидает готовности backend.

## Сохраненные возможности

Таблица студентов, подробная карточка, создание, редактирование с заполненными текущими данными и удаление. Сохранены все поля студента, клиентская и серверная валидация, адаптивная верстка и favicon с котом.

API сохраняет GET списка и отдельной записи, POST, PUT, PATCH, DELETE и QUERY. Поиск, фильтрация, сортировка и пагинация выполняются на сервере. Фильтры работают по всем полям, включая заметки и ID. При количестве заполненных фильтров больше трех интерфейс использует QUERY с JSON-телом; в остальных случаях GET с параметрами.

USER просматривает список и карточки. ADMIN может изменять записи. Кнопки изменения скрыты для USER; прямой переход на страницу создания или редактирования перенаправляет его на список. Backend независимо проверяет роли и возвращает 403 при запрещенной операции.

## Авторизация

Страницы `/login`, `/register` и `/profile` отвечают за вход, регистрацию и профиль. Pinia хранит текущего пользователя в памяти приложения.

Access- и refresh-токены хранятся в cookies с `HttpOnly` и `SameSite=Lax`. JavaScript не читает эти токены и не сохраняет их в localStorage. При истечении access-токена клиент один раз обновляет пару через `/api/auth/refresh` и повторяет запрос. Сервер атомарно потребляет старый refresh, а версии сессии не позволяют применять поздние ответы после выхода. Refresh-токен после обновления заменяется; выход отзывает его и удаляет cookies.

Перед изменяющими запросами и QUERY клиент получает CSRF-токен через `GET /api/auth/csrf` и передает его в заголовке, указанном сервером. Этот токен хранится только в памяти JavaScript. Токены авторизации в JSON не возвращаются.

`COOKIE_SECURE=false` нужен для локального HTTP-запуска. Для размещения за HTTPS следует установить `COOKIE_SECURE=true`.

## Bruno

Импортировать папку `bruno`, выбрать окружение `local` и указать пароли администратора и тестового пользователя во вкладке Secrets. Для другого порта изменить `baseUrl`. В коллекции 37 запросов, включая QUERY. Выполнять их в порядке коллекции; cookies сохраняет Bruno. Сценарий ролей создает отдельную учебную запись и затем удаляет ее; он не зависит от ID существующего студента. Проверка refresh после выхода повторно предъявляет сохраненный старый токен. Значения JWT не нужно копировать вручную или записывать в окружение.

## Реактивность

RxJS обрабатывает изменения поиска и фильтров, задерживает запрос при наборе текста и отменяет устаревшую загрузку списка. Подписка освобождается при уходе со страницы. Эта логика вынесена из компонентов в отдельный модуль. Новый фильтр сразу отменяет прежнюю загрузку, затем начинается пауза 300 мс перед новым запросом.
