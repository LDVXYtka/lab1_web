# Лабораторная 5: Nuxt

Nuxt 4 + Pinia + RxJS, Java Spring Boot + jOOQ, PostgreSQL 18. Nginx передает страницы серверу Nuxt, API и SSE серверу Java. Авторизация, проверки прав, бизнес-логика и БД остаются в Java.

## Запуск

Нужен запущенный Docker Desktop с Linux containers. В этой папке уже настроен локальный `.env` и отдельный том с копией данных лабы 4. Вход администратора сохранен из лабы 4. Исходная лаба и ее том не используются при запуске.

На новом компьютере скопировать `.env.example` в `.env`, заполнить три поля. JWT_SECRET: минимум 32 ASCII-символа. ADMIN_PASSWORD: 8–72 печатных ASCII-символа без пробелов. При отсутствии тома создадутся учебные студенты и администратор `admin`.

```sh
docker compose up --build -d
```

Сайт: http://localhost:8085, Swagger: http://localhost:8085/swagger-ui/index.html. Порт меняется через HTTP_PORT в `.env`. Остановка: `docker compose stop`. Данные остаются в томе `web-lab5_postgres_data`. Не удалять том, если данные нужны.

## Особенности переноса

- Страницы списка, карточки, редактирования и профиля получают начальные данные при SSR. Файловые маршруты и middleware заменяют ручной Vue Router.
- Состояние Pinia, HTTP-клиент, CSRF и refresh изолированы на каждый SSR-запрос. Все полученные Set-Cookie передаются браузеру. Токены не попадают в HTML или web storage.
- После успешного входа или выхода в localStorage сохраняется только отметка смены сессии: время и случайное число, без пользователя и токенов. Событие storage перезагружает остальные вкладки. При загрузке и возврате страницы проверяется, не сменилась ли сессия после начала навигации. Профиль, права и кеш заново загружаются через SSR с текущими cookies; формы предыдущего аккаунта закрываются.
- Недоступное хранилище не мешает входу и выходу. Если браузер запретил запись метки, соседнюю вкладку нужно обновить вручную.
- Вход, выход и refresh используют общий Web Lock вкладок и проходят через Nuxt к Java. Одновременные SSR и браузерные запросы одной сессии объединяют refresh по хешу cookie. Операции одной цепочки выполняются последовательно, ее состояние сохраняется до завершения всех присоединившихся ответов. Перед присоединением Java проверяет CSRF через POST /api/auth/csrf. Новый запрос с уже использованной cookie не получает этот ответ повторно. Проверка и выдача токенов остаются в Java.
- Cookies имеют имена `lab5AccessToken`, `lab5RefreshToken`, `lab5CsrfToken`, чтобы не пересекаться с lab4 на другом порту localhost. Refresh имеет Path=/ для прямого SSR после истечения access.
- Кеш студентов хранится в состоянии конкретного приложения Nuxt, переносится в браузер вместе с SSR-данными. Ключ включает пользователя, ресурс и все параметры выборки. Срок 30 секунд, максимум 50 записей. Общего серверного кеша пользователей и HTML нет.
- Успешные изменения очищают кеш. PostgreSQL NOTIFY и Java SSE очищают его у других клиентов, обновляют список и открытую карточку. При переподключении данные перечитываются. Введенный текст формы редактирования сохраняется.
- RxJS сохраняет паузу 3000 мс после последнего изменения фильтра, немедленную отмену устаревшего чтения и обновление без повторной паузы. QUERY с CSRF используется при более чем трех непустых фильтрах или длинной строке параметров, чтобы допустимые заметки не превышали лимит URL у прокси.

## Разделение работы

Карим: `app/pages/index.vue`, `app/pages/students/`, компоненты студентов, `app/utils/students.js`, `studentSearch.js`, `studentEvents.js`, `validation.js`, `app/plugins/02.students.js`, стили и контейнерная интеграция. Новая часть: SSR студентов, ключи и очистка кеша, live-обновления и сборка.

Данил: страницы login/register/profile, `app/utils/api.js`, `session.js`, `app/stores/auth.js`, `app/plugins/01.session.js`, `server/`, middleware, `app.vue`, `error.vue`. Новая часть: SSR-сессии, cookies и Set-Cookie, согласование refresh, изоляция HTTP-состояния и перенаправления.

Общий HTTP-клиент ведет Данил; параметры студенческих запросов относятся к части Карима. Docker ведет Карим, передачу auth-настроек проверяют вместе. В Java изменены имена и путь cookies, название cookie в Swagger и добавлен POST /api/auth/csrf для проверки CSRF при согласовании refresh.
