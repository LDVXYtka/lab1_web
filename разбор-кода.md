## Как устроена лаба целиком

Браузер загружает HTML, JavaScript и CSS у Nginx. JavaScript запускает Vue-приложение. Когда нужны студенты, код браузера отправляет `/api/requests` на тот же адрес сайта. Nginx пересылает запрос Spring-приложению. Spring проверяет доступ, контроллер принимает параметры, сервис организует операцию, репозиторий выполняет запрос через jOOQ к PostgreSQL. Ответ с данными возвращается в браузер.

Полученные данные и показанные элементы — разные вещи. Массив `students` хранится в памяти JavaScript. Таблица — элементы DOM, то есть дерева объектов документа в браузере. Vue связывает отображение с реактивным состоянием: после записи нового массива в `students.value` обновляет нужные элементы.

Состояние означает данные, описывающие текущую ситуацию: список, номер страницы, текст ошибки, идет ли загрузка. Локальное состояние принадлежит конкретному компоненту. Общее состояние текущего пользователя находится в Pinia и нужно сразу нескольким компонентам. Токены браузер хранит в HttpOnly cookies; пароль БД и секрет подписи JWT остаются серверными настройками.

Главная цепочка поиска:

```text
StudentFilters: пользователь изменил поле
    → событие change с новыми условиями
StudentsPage: собрать параметры и передать в поиск
studentSearch: дождаться 3 секунд без новых условий
    → getStudents → request → HTTP через Nginx
    → получить items и total
StudentsPage: записать ответ в реактивные переменные
StudentTable: показать переданный массив
```

Слово «метод» обычно означает функцию объекта. В файлах есть и обычные функции модуля. Для защиты важнее уметь сказать, кто вызывает функцию, с какими данными и какой результат получает.

## Минимум синтаксиса, чтобы читать остальные файлы

`import { ref } from 'vue'` получает именованную функцию из модуля. `export function getStudent` делает функцию доступной другим модулям. Верхние переменные обычного JS-модуля общие для использующих этот модуль частей данной вкладки. Код `<script setup>` подготавливает отдельный экземпляр компонента.

`async`-функция возвращает Promise: объект будущего результата. `await` позволяет дождаться его внутри этой функции. Пока сеть отвечает, браузер продолжает обрабатывать другие события. Ошибка ожидания попадает в ближайший подходящий `catch`. `finally` выполняется при завершении блока и после успеха, и после ошибки.

`data => ...` — стрелочная функция. В `.then(data => ...)` она получает успешный результат Promise. В `.catch(error => ...)` обрабатывает отказ. `throw error` передает ошибку выше: вызывающая страница может показать ее пользователю.

`options = {}` задает пустой объект по умолчанию. `{ signal }` сокращает `{ signal: signal }`. `{ ...filters }` копирует собственные перечисляемые свойства в новый объект; это поверхностная копия. Для наших строк и простых значений достаточно такой копии.

`===` проверяет строгое равенство, `!==` — неравенство. `&&` означает, что должны выполниться все условия, `||` выбирает следующую часть при ложном первом значении. `?.` прекращает обращение, если слева `null` или `undefined`. Поэтому `signal?.throwIfAborted()` допускает вызов без сигнала. `value ?? ''` подставляет пустую строку только для `null` и `undefined`.

## Синтаксис Vue, который встретится в каждом компоненте

Файл `.vue` объединяет `<script setup>`, `<template>` и при необходимости `<style scoped>`. В script находятся данные и функции экземпляра, template описывает отображение, style его оформление. Vite с плагином Vue преобразует этот синтаксис в браузерные JavaScript и CSS. Сборка происходит заранее; обработчики кнопок выполняются уже в браузере.

`ref(0)` создает реактивный объект со свойством value. В JavaScript пишем `total.value = 12`, в шаблоне достаточно `{{ total }}`: Vue разворачивает нашу верхнеуровневую ссылку. Const запрещает заменить саму ссылку total, но разрешает менять ее свойство. Ref может хранить и массив, поэтому `students.value = data.items` допустимо.

`reactive({ name: '' })` возвращает реактивный объект, поля которого меняются напрямую: `form.name = 'Иван'`. Vue использует Proxy для отслеживания операций с объектом. Proxy — возможность JavaScript перехватывать чтение и запись свойств. Обычная копия строки из form.name сама не становится связанной реактивной переменной.

`computed(() => ...)` описывает значение, вычисляемое из других реактивных данных. Оно кешируется по зависимостям: например, число страниц зависит от количества записей и размера страницы. `watch(источник, обработчик)` выполняет действие после изменения источника: например, сообщает родителю о новых фильтрах. Вычислить значение и запустить побочное действие — разные задачи.

`defineProps` объявляет входные данные ребенка. `defineEmits` объявляет его сообщения родителю. Эти две функции внутри script setup являются макросами компилятора Vue; отдельный import для них не нужен. Импортированные компоненты, переменные и функции верхнего уровня доступны шаблону.

| Запись в шаблоне | Что означает |
| --- | --- |
| `{{ student.name }}` | Вывести значение как текст; произвольный HTML из строки не исполняется |
| `:student="student"` | Передать значение JavaScript; двоеточие сокращает v-bind |
| `@save="save"` | Вызвать функцию save при событии save; @ сокращает v-on |
| `@submit.prevent="submit"` | Вызвать обработчик и отменить обычную отправку формы браузером |
| `v-model="form.name"` | Связать значение поля и данные формы в обоих направлениях |
| `v-if="student"` | Создать блок только при истинном условии; при ложном удалить |
| `v-else-if`, `v-else` | Следующие ветки того же условного выбора |
| `v-for="student in students"` | Повторить фрагмент для элементов массива |
| `:key="student.id"` | Сохранить идентичность записи при перестановке элементов |
| `:disabled="busy"` | Сделать элемент недоступным, пока busy истинно |

`v-show` в разобранном коде не используется, но на защите его могут сравнить с v-if: он оставляет элемент в DOM и переключает CSS display. Ключом строки выбран ID, потому что он относится к студенту, а индекс массива относится к позиции, которая меняется при сортировке.

`onMounted` регистрирует действие после монтирования компонента, `onUnmounted` — при его удалении. Это хуки жизненного цикла: функции, вызываемые Vue на определенных этапах существования экземпляра. Браузерные запросы и подписки сторонних библиотек останавливаем предусмотренным для них способом.

Scoped CSS ограничивает правила компонента через служебные атрибуты элементов и дополненные селекторы. Это преобразование сборки, а не Shadow DOM. Общие правила из styles.css продолжают применяться. Поэтому у нас 12 компонентов, 11 собственных блоков scoped и отдельный общий CSS.

## `frontend/src/api.js`: главное — `request()`

### Зачем этот файл

Все страницы должны уметь отправлять запросы, получать понятные ошибки и восстанавливать доступ при истекшем access-токене. Если повторить это в каждом компоненте, легко получить разное поведение. В `api.js` собрана общая работа HTTP. Страница выбирает операцию и показывает результат, файл API занимается отправкой и чтением ответа.

Раздели три функции: `send` подготавливает и отправляет запрос; `readResponse` читает и проверяет ответ; `request` связывает их и добавляет один сценарий восстановления сессии.

### Что получает и возвращает `request`

Пример вызова из `getStudent`:

```js
request('GET', '/api/requests/7', undefined, { signal })
```

| Аргумент | Смысл |
| --- | --- |
| `method` | HTTP-метод: GET, POST, PUT, DELETE или QUERY |
| `url` | Путь API, например `/api/requests/7` |
| `data` | Объект для тела запроса; `undefined` означает отсутствие тела |
| `options.signal` | Сигнал отмены от браузерного AbortController |
| `options.auth` | При `false` отключает попытку refresh и уведомление об истекшей сессии; используется у операций входа/выхода |
| `options.notifyExpired` | При `false` отключает глобальное уведомление об окончательном 401, сохраняя саму попытку refresh |

В результате получаем Promise с разобранными данными: например, объектом студента. Для успешного пустого ответа результат `null`. При неудаче Promise отклоняется с объектом Error. Из него страница читает `message`, а при наличии также `status` и `fields`.

### Весь `request()` с пояснениями

Это учебная копия актуальной функции. Комментарии поясняют смысл блоков.

```js
export async function request(method, url, data, options = {}) {
  const version = sessionVersion // Запоминаем, к какой сессии относился запрос
  try {
    let response = await send(method, url, data, options.signal)

    // Восстановление допустимо для 401 защищенного запроса,
    // пока сессия та же и пользователь не выполняет выход
    if (response.status === 401 && options.auth !== false && version === sessionVersion && !loggingOut) {
      await refreshSession() // Получить новые cookies через refresh-токен
      options.signal?.throwIfAborted() // Не продолжать отмененный запрос
      if (version === sessionVersion && !loggingOut) {
        response = await send(method, url, data, options.signal) // Один повтор
      }
    }

    return await readResponse(response) // Данные ответа или ошибка внутри try
  } catch (error) {
    options.signal?.throwIfAborted() // При отмене передать именно отмену
    if (error.status === 401 && options.auth !== false && options.notifyExpired !== false && version === sessionVersion && !loggingOut) {
      sessionExpired() // Сообщить приложению: требуется новый вход
    }
    throw error // Передать отказ вызывающей странице
  }
}
```

### Почему сначала проверяется статус, а не вызывается catch

`fetch` возвращает объект Response и при HTTP-ошибках вроде 401 или 404. Это состоявшийся обмен с сервером. Отказ самого fetch обычно связан с сетевой проблемой или отменой. Поэтому наш код сам проверяет `response.status`, а позже `readResponse` превращает неуспешный HTTP-ответ в Error. Это поведение описано в [документации fetch](https://developer.mozilla.org/en-US/docs/Web/API/Window/fetch).

### Разбор условий первого if

`response.status === 401`: сервер не принял аутентификацию. Возможная причина — истек access-токен. При 403 refresh не запускается: повторное получение токена само по себе не добавляет прав и не исправляет CSRF.

`options.auth !== false`: обычный запрос по умолчанию участвует в восстановлении. Но неудачный логин не должен запускать refresh предыдущего пользователя или автоматически показывать «сессия истекла». Поэтому вход передает `auth: false`. Это настройка нашего клиента, которую сервер не видит как разрешение на доступ.

`version === sessionVersion`: запрос относится к текущей сессии. Представь: старый запрос начат, пользователь вышел и вошел заново, потом пришел прежний 401. Нельзя из-за него восстанавливать или очищать новую сессию. Счетчик увеличивается при смене сессии, а локальная `version` сохраняет старый номер.

`!loggingOut`: пользователь сейчас не выходит. В момент выхода нельзя запускать восстановление доступа, которое противоречило бы выходу.

После `await refreshSession()` эти условия проверяются снова, потому что за время ожидания пользователь мог выйти. Значение, проверенное до ожидания, не гарантирует состояние после ожидания.

### Почему запрос повторяется ровно один раз

В функции один `if`, внутри него один повтор `send`. Нет цикла и рекурсивного вызова `request`. Повторный 401 обрабатывается при чтении ответа и приводит к ошибке. Такой предел защищает от бесконечного восстановления неработающей сессии.

### Почему `return await readResponse`, а не просто `return readResponse`

`readResponse` асинхронна: ей надо прочитать тело ответа. Здесь `await` позволяет получить ее ошибку внутри текущего `try/catch`. Без ожидания функция вернула бы Promise наружу, и его последующее отклонение не обработал бы этот локальный catch. Это важно для окончательного 401 после повторной отправки. Сам механизм ожидания и исключений описан в [документации await](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/await).

### Что делает catch

Сначала проверяет отмену. Отмененный поиск не должен выдавать сообщение о пропавшем сервере или истекшей сессии. Если отказ является актуальным 401 защищенного запроса и глобальное уведомление не отключено, вызывается `sessionExpired()`.

Сам `api.js` не импортирует Router и не выбирает страницу входа. В `main.js` заранее зарегистрирован обработчик: очистить известного пользователя и перейти на `/login?expired=1`. После уведомления `throw error` сохраняет ошибку для вызывающего кода.

### Три сценария, которые надо восстановить словами

**Обычный успех.** `getStudent(7)` вызывает request. `send` получает Response со статусом 200. Ветка 401 пропускается. `readResponse` читает JSON. Страница получает объект студента и кладет его в `student.value`.

**Access истек, refresh действителен.** Первый GET получает 401. `refreshSession` отправляет POST на `/api/auth/refresh`; браузер прикладывает refresh-cookie. Сервер устанавливает новые cookies. После проверки отмены и версии повторяется исходный GET. Из ответа 200 читается студент. Пользователь продолжает работу.

**Refresh недействителен.** Первый GET получает 401. Refresh тоже отвечает 401. `readResponse` внутри обновления создает Error с `status = 401`. Ожидание refresh выбрасывает ее в catch функции request. Зарегистрированный обработчик очищает состояние и открывает страницу входа. Исходный GET повторно не отправляется.

Если же refresh завершился сетевой ошибкой или, например, статусом 403, наружу пойдет именно этот отказ. Глобальный обработчик истекшей сессии вызывается для итоговой 401 при выполнении остальных условий. Первый 401 не означает безусловный переход на вход при любом результате восстановления.

**Короткий ответ преподавателю:** «request — общая функция HTTP-запроса. Она отправляет запрос, при 401 один раз пытается обновить сессию и повторяет операцию, затем разбирает ответ или передает ошибку. Дополнительные проверки не позволяют старому запросу повлиять на новую сессию или восстановить доступ во время выхода».

| --- | --- |
| `csrfToken` | Уже полученные имя заголовка и значение CSRF-токена в памяти вкладки |
| `csrfPromise` | Общая незавершенная загрузка CSRF, чтобы одновременно не отправлять одинаковые запросы |
| `refreshPromise` | Общая незавершенная операция refresh для нескольких получивших 401 запросов |
| `sessionVersion` | Номер текущей клиентской сессии для проверки старых ответов |
| `loggingOut` | Признак выполняющегося выхода |
| `sessionExpired` | Функция-обработчик окончательного истечения сессии; первоначально пустая |

Общая Promise означает: первый вызов запускает операцию, остальные ожидают тот же результат. После завершения `finally` убирает сохраненную Promise, чтобы следующая самостоятельная операция могла начаться заново. Это не кеш результата навсегда.

### `onSessionExpired(handler)`, `resetCsrf()`, `resetSession()`

`onSessionExpired` вызывается в `main.js`, получает функцию и сохраняет ее. Параметр handler — функция, а не уже выполненный переход.

`resetCsrf` забывает полученный CSRF-токен. При следующем нужном запросе он загрузится снова. Уже запущенную загрузку эта функция не отменяет.

`resetSession` увеличивает номер сессии и сбрасывает CSRF-кеш. Ее используют сценарии смены пользователя и выхода. Она не отправляет HTTP, не очищает cookies сама и не является выходом на сервере.

### `fetchResponse(url, options)`

Низкая обертка над браузерным fetch. Возвращает Response. Сетевую ошибку превращает в понятный текст «Сервер недоступен...». Если произошла отмена, передает исходную ошибку дальше. HTTP-статусы здесь еще не превращаются в ошибки приложения.

### `readResponse(response)`

Получает Response от HTTP-запроса. Для 204 возвращает `null`: тела нет. Для другого успешного пустого ответа тоже возвращает `null`. Иначе читает тело как текст и разбирает JSON.

Если JSON некорректен, формирует понятную ошибку и сохраняет HTTP-статус. Если JSON корректен, но `response.ok` ложно, берет `message` и `fields` из ответа и выбрасывает Error. `ok` соответствует диапазону успешных статусов 200–299. `fields` — ошибки отдельных полей формы, например занятого ИСУ. В успешном случае возвращает разобранный объект.

Тело Response читают один раз. Поэтому сначала получаем весь текст, затем самостоятельно разбираем его; после этого не пытаемся заново вызвать response.json для того же ответа.

### `getCsrf()`

Нужна перед изменяющим запросом. Если токен уже есть, возвращает его. Если получение идет, возвращает общую `csrfPromise`. Иначе отправляет GET `/api/auth/csrf`, читает ответ и запоминает объект с `headerName` и `token`. `cache: 'no-store'` просит браузер не использовать HTTP-кеш для этого получения.

CSRF-токен — проверка допустимости запроса, а не замена access-токена. JavaScript получает его из ответа API и передает в заголовке. Токены авторизации JS читать из HttpOnly cookies не должен.

### `send(method, url, data, signal)`

Создает объект заголовков. Для методов кроме GET, HEAD и OPTIONS получает CSRF и добавляет заголовок с выданным сервером именем. Сюда попадает и QUERY: так настроена защита нашего приложения.

Затем проверяет сигнал отмены. Формирует options с методом, заголовками и signal. Если `data !== undefined`, добавляет Content-Type JSON и сериализует объект через JSON.stringify. Наконец вызывает fetchResponse. JSON.stringify — преобразование объекта в строку формата JSON, подходящую для тела HTTP.

Cookies для нашего same-origin запроса браузер прикладывает сам. Отдельного Authorization с прочитанным из хранилища токеном этот файл не создает.

### `refreshSession()`

Использует `send` и `readResponse`, отправляя POST `/api/auth/refresh`. После успеха сбрасывает CSRF-кеш. Общая `refreshPromise` предотвращает несколько одновременных обменов одного refresh-токена. Это существенно: сервер заменяет использованный refresh-токен.

Внутри нет вызова request: неудачный refresh не пытается обновлять сам себя. Отмена одного исходного поиска не отменяет общий refresh, который может быть нужен другим запросам. После ожидания исходный request отдельно проверяет свой signal.

### `logoutSession()`

Помечает начало выхода и меняет номер сессии. Если refresh уже идет, ожидает его завершения, игнорируя его отказ для продолжения выхода. Потом отправляет POST logout с `auth: false`. В finally снимает признак выхода.

Зачем ждать refresh? Уже начатый ответ refresh может установить новые cookies. Если logout закончится раньше него, поздний refresh способен вернуть cookies после выхода. Порядок «дождаться refresh → выполнить logout» устраняет эту гонку. Если сам logout не удался, ошибка идет в App для сообщения; успешный выход и очистку пользователя завершает session.js.

### `getStudents(params, signal)`

Вызывается из RxJS-загрузки. Считает именно фильтры, исключая page, size, sort и order. При трех и менее фильтрах использует GET с URLSearchParams. При четырех и более отправляет QUERY с JSON-телом. Это сохраняет специальный метод из предыдущих лаб.

Перед QUERY копирует параметры, переводит id, dormitory, page и size в числа, international в boolean. Для JSON число 8 и строка "8" — разные типы. Поля ИСУ и комнаты остаются строками. Пример: name, group, dormitory, note дают четыре фильтра и запускают QUERY.

### `getStudent`, `saveStudent`, `deleteStudent`

`getStudent(id, signal)` делает GET одной записи; его используют карточка и редактирование. `saveStudent(id, student, signal)` при наличии id отправляет PUT, а без id POST. Вызывающий код получает сохраненного студента с id и может открыть карточку. `deleteStudent(id, signal)` отправляет DELETE; успешный результат пустой.

Эти функции выбирают URL, метод и данные. Одинаковую отправку, CSRF, refresh и ошибки выполняет request.

```js
let csrfToken = null
let csrfPromise = null
let refreshPromise = null
let sessionVersion = 0
let loggingOut = false
let sessionExpired = () => {}

export function onSessionExpired(handler) {
  sessionExpired = handler
}

export function resetCsrf() {
  csrfToken = null
}

export function resetSession() {
  sessionVersion++
  resetCsrf()
}

async function fetchResponse(url, options) {
  try {
    return await fetch(url, options)
  } catch (error) {
    if (error.name === 'AbortError' || options.signal?.aborted) {
      throw error
    }
    throw new Error('Сервер недоступен. Проверьте подключение и запуск приложения')
  }
}

async function readResponse(response) {
  if (response.status === 204) {
    return null
  }
  const text = await response.text()
  if (!text && response.ok) {
    return null
  }
  let body
  try {
    body = JSON.parse(text)
  } catch {
    const error = new Error(response.status >= 500
      ? 'Ошибка сервера. Попробуйте повторить запрос позже'
      : 'Сервер вернул некорректный ответ')
    error.status = response.status
    throw error
  }
  if (!response.ok) {
    const error = new Error(body.message || 'Не удалось выполнить запрос')
    error.status = response.status
    error.fields = body.fields || {}
    throw error
  }
  return body
}

async function getCsrf() {
  if (csrfToken) {
    return csrfToken
  }
  if (!csrfPromise) {
    csrfPromise = fetchResponse('/api/auth/csrf', { method: 'GET', cache: 'no-store' })
      .then(readResponse)
      .then(token => {
        csrfToken = token
        return token
      })
      .finally(() => {
        csrfPromise = null
      })
  }
  return csrfPromise
}

async function send(method, url, data, signal) {
  const headers = {}
  if (!['GET', 'HEAD', 'OPTIONS'].includes(method)) {
    const csrf = await getCsrf()
    headers[csrf.headerName] = csrf.token
  }
  signal?.throwIfAborted()
  const options = { method, headers, signal }
  if (data !== undefined) {
    headers['Content-Type'] = 'application/json'
    options.body = JSON.stringify(data)
  }
  return fetchResponse(url, options)
}

async function refreshSession() {
  if (!refreshPromise) {
    refreshPromise = send('POST', '/api/auth/refresh')
      .then(readResponse)
      .then(() => resetCsrf())
      .finally(() => {
        refreshPromise = null
      })
  }
  return refreshPromise
}

export async function request(method, url, data, options = {}) {
  const version = sessionVersion
  try {
    let response = await send(method, url, data, options.signal)
    if (response.status === 401 && options.auth !== false && version === sessionVersion && !loggingOut) {
      await refreshSession()
      options.signal?.throwIfAborted()
      if (version === sessionVersion && !loggingOut) {
        response = await send(method, url, data, options.signal)
      }
    }
    return await readResponse(response)
  } catch (error) {
    options.signal?.throwIfAborted()
    if (error.status === 401 && options.auth !== false && options.notifyExpired !== false && version === sessionVersion && !loggingOut) {
      sessionExpired()
    }
    throw error
  }
}

export async function logoutSession() {
  loggingOut = true
  resetSession()
  try {
    if (refreshPromise) await refreshPromise.catch(() => {})
    await request('POST', '/api/auth/logout', undefined, { auth: false })
  } finally {
    loggingOut = false
  }
}

export function getStudents(params, signal) {
  const filters = Object.keys(params).filter(name => !['page', 'size', 'sort', 'order'].includes(name))
  if (filters.length > 3) {
    const data = { ...params }
    for (const name of ['id', 'dormitory', 'page', 'size']) {
      if (data[name] !== undefined) {
        data[name] = Number(data[name])
      }
    }
    if (data.international !== undefined) {
      data.international = data.international === 'true'
    }
    return request('QUERY', '/api/requests', data, { signal })
  }
  return request('GET', '/api/requests?' + new URLSearchParams(params), undefined, { signal })
}

export function getStudent(id, signal) {
  return request('GET', '/api/requests/' + id, undefined, { signal })
}

export function saveStudent(id, student, signal) {
  if (id) {
    return request('PUT', '/api/requests/' + id, student, { signal })
  }
  return request('POST', '/api/requests', student, { signal })
}

export function deleteStudent(id, signal) {
  return request('DELETE', '/api/requests/' + id, undefined, { signal })
}
```

## `frontend/src/studentSearch.js`: RxJS без магии

### Термины перед кодом

Поток — значения, поступающие во времени: условия фильтра меняются при вводе, результаты запросов приходят позже. Observable описывает получение значений. Подписка запускает или подключает получение, а ее unsubscribe прекращает участие. Subject позволяет нашему коду самому отправлять события методом next. Оператор в pipe строит новый поток на основе предыдущего.

### `loadStudents(params)`

Вызывается внутренним оператором поиска. Возвращает Observable. Когда на него подписываются, создаются AbortController и запрос getStudents. После успеха subscriber получает данные через next, затем complete. При ошибке получает error, если операция не отменена. Возвращенная из функции создания Observable очистка вызывает abort.

Таким образом, именно очистка связывает отписку RxJS с отменой HTTP. Один switchMap без подходящего источника не обязан отменять произвольную сетевую операцию.

### `createStudentSearch()` и два входа

Каждая страница списка создает свой поиск. Функция возвращает три объекта: changes принимает новые условия и delay, refresh принимает сообщения «перечитать примененные условия», results выдает состояния отображения.

У состояния результата три поля. data — успешный ответ или null, loading — идет ли ожидание/загрузка, error — текст ошибки. Сам модуль не знает ни ref, ни таблицу: страница подписывается и сама переносит значения в Vue.

### Внешний switchMap и timer

Из changes приходит `{ params, delay }`. Внешний switchMap отписывается от прежней работы и создает timer для нового набора. Ввод фильтров передает delay 3000. Новое изменение сразу отменяет прежний таймер или запрос, а новый отсчет начинается заново. Первая загрузка и смена страницы передают delay ноль.

Таймер с нулем выполняется асинхронно без намеренной трехсекундной паузы. Поэтому «сразу» здесь означает отсутствие задержки фильтра, а не синхронный HTTP в той же строке.

### Средний switchMap и `merge(of(null), refresh)`

Когда таймер сработал, начинается получение событий для данного набора params. `of(null)` сразу выдает одно стартовое событие. merge объединяет его с будущими refresh. Благодаря стартовому событию запрос произойдет и без чужих изменений.

Значение null не является результатом поиска; здесь оно только повод выполнить загрузку. Уведомление refresh тоже не несет готовый массив. Примененные params сохранены в этой ветке потока.

Пока новый таймер фильтра еще идет, refresh в этой ветке не слушается. Уведомление не сокращает трехсекундную паузу: после нее запрос и так прочитает актуальную базу.

### Внутренний switchMap, map, catchError, startWith

Каждый старт или refresh вызывает loadStudents с примененными params. Если новый refresh пришел до ответа, прежняя загрузка отменяется. map оформляет успех. catchError превращает отказ конкретной загрузки в объект с error. Он стоит внутри ветки запроса, поэтому следующая загрузка остается возможной.

Внутренний startWith сообщает загрузку перед каждым HTTP. Внешний startWith сообщает ожидание сразу при новых условиях, еще до истечения timer. Страница одним loading обозначает оба этапа.

Порядок трех switchMap стоит объяснить словами: новые условия выбирают новую цепочку; окончание паузы включает старт и уведомления; каждое уведомление выбирает актуальную HTTP-загрузку. Механизм переключения подтверждается [реализацией switchMap RxJS 7.8.2](https://github.com/ReactiveX/rxjs/blob/7.8.2/src/internal/operators/switchMap.ts).

**Пример времени:** ввел «Ив», через секунду «Иван». Первый таймер отменяется. Запрос с «Иван» начнется через три секунды после второго изменения. Когда запрос завершился и другой человек изменил запись, refresh запускает перечитывание без новой трехсекундной задержки.

<details>
<summary>Полный код: frontend/src/studentSearch.js</summary>

```js
import { Observable, Subject, timer, switchMap, map, catchError, of, merge, startWith } from 'rxjs'
import { getStudents } from './api'

function loadStudents(params) {
  return new Observable(subscriber => {
    const controller = new AbortController()
    getStudents(params, controller.signal)
      .then(data => {
        subscriber.next(data)
        subscriber.complete()
      })
      .catch(error => {
        if (!controller.signal.aborted) {
          subscriber.error(error)
        }
      })
    return () => controller.abort()
  })
}

export function createStudentSearch() {
  const changes = new Subject()
  const refresh = new Subject()
  const results = changes.pipe(
    switchMap(({ params, delay = 0 }) => timer(delay).pipe(
      switchMap(() => merge(of(null), refresh).pipe(
        switchMap(() => loadStudents(params).pipe(
          map(data => ({ data, loading: false, error: '' })),
          catchError(error => of({ data: null, loading: false, error: error.message })),
          startWith({ data: null, loading: true, error: '' })
        ))
      )),
      startWith({ data: null, loading: true, error: '' })
    ))
  )
  return { changes, refresh, results }
}
```

## `frontend/src/studentEvents.js`: браузер получает уведомления

### `watchStudents(onChange)`

Вызывается при монтировании списка или карточки. Получает callback — функцию, которую надо вызвать после сообщения сервера. Возвращает функцию очистки для onUnmounted. У каждой подписки свои EventSource, таймер и контроллер.

EventSource — браузерное API для SSE: сервер присылает события по открытому HTTP-соединению. На первоначальном подключении отправляемых из JavaScript токенов нет: браузер передает подходящие cookies.

### Вложенная `connect()`

Если работа уже отменена, ничего не делает. Иначе открывает `/api/requests/events` и регистрирует три обработчика. `ready` вызывает onChange без id: нужно перечитать состояние после подключения. `students-changed` преобразует строковый id события в число и передает его callback. `onerror` закрывает соединение и ставит попытку восстановления через секунду.

Список на любое изменение запускает refresh. Карточка обновляется при ready либо при совпадении присланного id со своим. В событии нет полной записи: обычный API возвращает данные с актуальными фильтрами и проверками доступа.

### Вложенная асинхронная `reconnect()`

Перед повторным подключением вызывает request GET `/api/auth/me`. Это позволяет использовать общий механизм refresh, которого обычный EventSource не выполняет через наш request. При успехе снова connect. При отказе и продолжающей существовать странице новая попытка назначается через три секунды. При окончательном 401 общий обработчик переводит на вход; уход со страницы вызывает очистку.

### Первоначальный запуск и возвращенная функция

Первый connect выполняется сразу. Возвращаемая функция вызывает abort для возможной проверки профиля, clearTimeout для запланированного восстановления и close для SSE. AbortController сам по себе EventSource не закрывает: поэтому close указан отдельно.

Почему у сервера ограничено время SSE-соединения? Через примерно 30 секунд клиент подключается снова, а сервер заново проверяет аутентификацию. После повторного подключения ready заставляет перечитать данные, даже если какие-то уведомления были пропущены.

**Ответ преподавателю:** «Vue замечает изменения наших объектов в браузере. О чужой записи в базе сначала сообщает SSE. Мы перечитываем API, обновляем ref, и только после этого Vue меняет интерфейс».

<details>
<summary>Полный код: frontend/src/studentEvents.js</summary>

```js
import { request } from './api'

export function watchStudents(onChange) {
  const controller = new AbortController()
  let events
  let retry

  function connect() {
    if (controller.signal.aborted) return
    events = new EventSource('/api/requests/events')
    events.addEventListener('ready', () => onChange())
    events.addEventListener('students-changed', event => onChange(Number(event.data)))
    events.onerror = () => {
      events.close()
      retry = setTimeout(reconnect, 1000)
    }
  }

  async function reconnect() {
    try {
      await request('GET', '/api/auth/me', undefined, { signal: controller.signal })
      connect()
    } catch {
      if (!controller.signal.aborted) retry = setTimeout(reconnect, 3000)
    }
  }

  connect()
  return () => {
    controller.abort()
    clearTimeout(retry)
    events.close()
  }
}
```

## Как связаны страницы и небольшие компоненты

В проекте 12 файлов `.vue`: четыре небольших компонента, семь страниц и корневой `App`. Страница тоже является Vue-компонентом. Разница в назначении: страницу выбирает маршрутизатор по адресу, а таблицу или форму страница вставляет внутрь себя.

Здесь разбираем семь файлов студенческого интерфейса и общих сообщений. Их JavaScript выполняется в браузере. `props` передают входные данные ребёнку, событие сообщает родителю о действии. Родитель вызывает API, получает ответ и меняет состояние. Vue отражает это изменение в шаблоне. В текущей версии поиск ждёт **три секунды после последнего изменения**, а список и карточка получают уведомления об изменениях через SSE. Это уже отличается от старого варианта поиска с паузой 300 мс.

## StudentFilters.vue: собрать условия поиска

Файл [StudentFilters.vue](frontend/src/components/StudentFilters.vue) хранит поля фильтров и сообщает странице об их изменении. Сам HTTP он не отправляет.

`defineEmits(['change'])` объявляет событие `change`; переменная `emit` позволяет его отправить. `defaults` содержит исходные условия: пустые поисковые поля, сортировку по ID, возрастание и десять записей на странице. `reactive({ ...defaults })` создаёт отдельный изменяемый объект `filters`, связанный с интерфейсом.

**Наблюдатель `watch(filters, ...)`.** Vue вызывает его при изменении свойств фильтров. Он получает доступ к текущему объекту, делает поверхностную копию и передаёт её аргументом события `change`. Копия содержит простые значения, поэтому родителю не передаётся общий изменяемый объект полей. Родительский `changeFilters(values)` получает эту копию.

**Функция `reset()`.** Вызывается кнопкой «Сбросить», аргументов не принимает. `Object.assign(filters, defaults)` переносит исходные свойства в существующий реактивный объект. Поля очищаются, сортировка и размер возвращаются к исходным; наблюдатель сообщает родителю об изменении. Отдельного возвращаемого результата нет.

Шаблон связывает поля с `filters` через `v-model`. Поля даты содержат строки год-месяц-день. Выбор иностранного статуса различает пустую строку «Все», строку `'true'` и строку `'false'`. `v-for="number in 8"` создаёт варианты общежитий от 1 до 8. Подписи связаны с полями через `for` и `id`.

`@submit.prevent` отменяет обычную отправку формы браузером, но **не запускает отдельный поиск**. Кнопки «Найти» в текущей версии нет: изменение автоматически проходит через наблюдатель. Трёхсекундную паузу задаёт родитель.

`style scoped` задаёт сетку: четыре колонки на широком экране, две до 900px, одна до 600px. Кнопка сброса занимает общую строку. Это оформление полей, оно не участвует в выборе HTTP-метода.

## StudentsPage.vue: управлять списком, запросами и событиями

[StudentsPage.vue](frontend/src/pages/StudentsPage.vue) объединяет фильтры, таблицу, сообщения и пагинацию. Именно здесь находится состояние списка.

`students` хранит записи текущей страницы, `total` общее количество подходящих записей, `page` номер страницы. `filters` — текущий набор условий в `ref`, который можно заменить целиком. `loading` и `deleting` различают чтение и удаление. `error` и `success` содержат сообщения. `auth` даёт роль пользователя для интерфейса.

`pageCount` — `computed`: число страниц получается из `total` и размера. Для 23 записей по 10 нужно три страницы: делим и округляем вверх. Минимум одна страница сохраняет понятный вывод при пустом списке. `subscription` хранит подписку на результаты поиска, `stopEvents` — функцию отключения SSE. Контроллер страницы используется для удаления; сетевые чтения поиска имеют собственные контроллеры.

**`load(delay = 0)`.** Вызывается при открытии, переходе между страницами, изменении фильтров и после удаления. Аргумент — задержка в миллисекундах. Функция собирает `page`, перебирает условия, приводит значения к строкам и убирает пробелы. Пустые условия не добавляет. Затем передаёт `{ params, delay }` в `search.changes.next`. Это передача параметров механизму поиска, который уже вызывает API. Значимого результата функция не возвращает.

**`changeFilters(values)`.** Обработчик события дочерней формы. Получает новые условия, заменяет `filters.value`, устанавливает первую страницу и вызывает `load(3000)`. Механизм поиска отменяет предыдущую ветку и начинает новую паузу. Поэтому каждое последующее изменение заново отсчитывает три секунды. Первоначальная загрузка и пагинация используют задержку ноль.

**`changePage(value)`.** Вызывается кнопками «Назад» и «Вперёд». Получает новый номер, записывает его и вызывает `load()`. Кнопки отключаются при загрузке и выходе за доступные границы.

**`remove(student)`.** Получает объект строки из события таблицы. Останавливает повторный вызов и спрашивает подтверждение. Включает `deleting`, очищает сообщения, ждёт `deleteStudent(student.id, signal)`. После успеха показывает сообщение, при удалении последней строки непервой страницы уменьшает номер и перечитывает список. Ошибка отображается, если операция не отменена; `finally` всегда снимает `deleting`.

**`onMounted`.** Сначала подключает обработчик результатов. Каждый результат содержит загрузку, ошибку и при успехе данные. `items` заменяет `students`, `total` обновляет количество. Если после изменения данных текущая страница стала больше последней, номер ограничивается и выполняется повторная загрузка. Затем запускается начальное чтение и подключается `watchStudents`: уведомление сервера вызывает `search.refresh.next()`.

SSE — канал уведомлений от сервера к браузеру. Уведомление не содержит готовую таблицу: оно заставляет перечитать данные с текущими условиями. Если пользователь ещё меняет фильтры и идёт пауза, уведомление не обходит её; после паузы будет выполнен запрос актуальных данных.

**`onUnmounted`.** Отменяет удаление, отключает подписку поиска, завершает оба источника `changes` и `refresh`, вызывает `stopEvents`. Таким образом ушедшая страница прекращает получать данные.

Шаблон передаёт таблице массив, роль и занятость. Событие `delete` связано с `remove`. Надписи чтения и удаления независимы; сообщение «Студенты не найдены» появляется после завершения загрузки без ошибки при пустом массиве. Scoped-стили располагают информационную панель и пагинацию через Flex с переносом.

```vue
<script setup>
import { computed, onMounted, onUnmounted, ref } from 'vue'
import { useAuthStore } from '../stores/auth'
import { deleteStudent } from '../api'
import { createStudentSearch } from '../studentSearch'
import { watchStudents } from '../studentEvents'
import MessageBox from '../components/MessageBox.vue'
import StudentFilters from '../components/StudentFilters.vue'
import StudentTable from '../components/StudentTable.vue'

const auth = useAuthStore()
const students = ref([])
const total = ref(0)
const page = ref(1)
const filters = ref({ sort: 'id', order: 'asc', size: '10' })
const loading = ref(true)
const deleting = ref(false)
const error = ref('')
const success = ref('')
const search = createStudentSearch()
const controller = new AbortController()
const pageCount = computed(() => Math.max(1, Math.ceil(total.value / Number(filters.value.size))))
let subscription
let stopEvents

function load(delay = 0) {
  const params = { page: page.value }
  for (const [name, value] of Object.entries(filters.value)) {
    const text = String(value).trim()
    if (text !== '') params[name] = text
  }
  search.changes.next({ params, delay })
}

function changeFilters(values) {
  filters.value = values
  page.value = 1
  load(3000)
}

function changePage(value) {
  page.value = value
  load()
}

async function remove(student) {
  if (deleting.value || !window.confirm('Удалить студента ' + student.name + '?')) return
  deleting.value = true
  error.value = ''
  success.value = ''
  try {
    await deleteStudent(student.id, controller.signal)
    if (controller.signal.aborted) return
    success.value = 'Студент удален'
    if (students.value.length === 1 && page.value > 1) page.value--
    load()
  } catch (failure) {
    if (!controller.signal.aborted) error.value = failure.message
  } finally {
    deleting.value = false
  }
}

onMounted(() => {
  subscription = search.results.subscribe(result => {
    loading.value = result.loading
    error.value = result.error
    if (result.data) {
      students.value = result.data.items
      total.value = result.data.total
      if (page.value > pageCount.value) {
        page.value = pageCount.value
        load()
      }
    }
  })
  load()
  stopEvents = watchStudents(() => search.refresh.next())
})

onUnmounted(() => {
  controller.abort()
  subscription.unsubscribe()
  search.changes.complete()
  search.refresh.complete()
  stopEvents()
})
</script>

<template>
  <section class="page">
    <MessageBox :text="error" />
    <MessageBox :text="success" success />
    <StudentFilters @change="changeFilters" />
    <div class="info-panel">
      <p>Студентов: {{ total }}</p>
      <RouterLink v-if="auth.isAdmin" to="/students/new" class="button">Добавить студента</RouterLink>
    </div>
    <p v-if="loading">Загрузка студентов...</p>
    <p v-if="deleting">Удаление студента...</p>
    <StudentTable :students="students" :is-admin="auth.isAdmin" :busy="deleting || loading" @delete="remove" />
    <p v-if="!loading && !error && students.length === 0">Студенты не найдены</p>
    <div class="pagination">
      <button type="button" :disabled="loading || page <= 1" @click="changePage(page - 1)">Назад</button>
      <span>Страница {{ page }} из {{ pageCount }}</span>
      <button type="button" :disabled="loading || page >= pageCount" @click="changePage(page + 1)">Вперед</button>
    </div>
  </section>
</template>

<style scoped>
.info-panel {
  display: flex;
  justify-content: space-between;
  align-items: center;
  flex-wrap: wrap;
  gap: 1rem;
  margin: 1rem 0;
}

  align-items: center;
  flex-wrap: wrap;
  gap: 1rem;
  margin: 1rem 0;
}
```

## StudentTable.vue: показать переданные записи

[StudentTable.vue](frontend/src/components/StudentTable.vue) получает три props: обязательный массив `students`, признак `isAdmin` и занятость `busy`. Собственной загрузки и массива записей здесь нет. `defineEmits(['delete'])` объявляет исходящее событие.

**`formatDate(date)`.** Шаблон вызывает функцию для даты каждой строки. Аргумент — строка вроде `2026-11-10`. `split('-')` разбивает её на части, `reverse()` разворачивает порядок, `join('.')` возвращает `10.11.2026`. Исходная запись студента не меняется.

`v-for` повторяет строку для каждого объекта. `:key="student.id"` связывает строку с конкретной записью независимо от сортировки. Ячейки выводят поля, иностранный статус превращается в «Да» или «Нет». Ссылка «Подробнее» строит адрес карточки по ID. Администратор дополнительно видит редактирование и удаление. Кнопка отправляет `$emit('delete', student)`, поэтому родитель получает выбранный объект. `busy` блокирует повторное нажатие.

Условное скрытие кнопки помогает пользователю, но право DELETE всё равно проверяет сервер. Переход RouterLink и событие компонента сами не являются запросами к базе.

## StudentForm.vue: подготовить и проверить ввод

[StudentForm.vue](frontend/src/components/StudentForm.vue) используется и для создания, и для редактирования. Получает `student`, `busy`, `backendFields`; отправляет событие `save`.

`form` — локальный реактивный объект восьми полей. `errors` хранит местные ошибки, `submitted` факт первой попытки. `fieldErrors` вычисляется объединением серверных и местных сообщений; при одинаковом поле местное имеет приоритет. `maxTerm` задаёт конец текущего года для максимальной даты.

Для `backendFields` исходное значение задано функцией `() => ({})`: каждый экземпляр формы получает свой пустой объект. В шаблоне верхнеуровневые ref автоматически разворачиваются, поэтому там пишется `fieldErrors.name`, а в JavaScript для `errors` требуется `.value`. Родительские props используются как вход; пользователь редактирует отдельный локальный `form`.

**Наблюдатель входного `student`.** Вызывается сразу благодаря `immediate` и затем при замене входной записи. Копирует свойства студента в локальные поля. Это нужно и при первом показе: родитель создаёт редактируемую форму уже после GET. Оператор `??` заменяет null/undefined пустой строкой, но сохраняет `false` иностранного статуса.

**`getStudentData()`.** Вызывается проверками и отправкой, аргументов нет. Возвращает отдельный объект из текущих полей: очищает края строк, сокращает повторные пробелы ФИО, переводит группу в верхний регистр, превращает общежитие в число или null. ИСУ и комната остаются строками, дата и флажок сохраняют значения. Значит, проверяем подготовленные данные, которые затем собираемся отправить.

**Наблюдатель `form`.** После первой попытки отправки заново вызывает `validateStudent(getStudentData())` при исправлении полей. До неё не показывает ошибки пустой новой формы. Серверные ошибки родитель очищает перед следующей попыткой сохранения.

**`submit(event)`.** Браузер вызывает обработчик при отправке формы. Если `busy`, он сразу завершается. Иначе запоминает попытку, готовит данные, возвращает нормализованные ФИО и группу в поля, получает ошибки `validateStudent`. Затем перебирает элементы текущей формы и дополнительно вызывает HTML `checkValidity`. Стандартное сообщение добавляется, если собственной ошибки этого поля ещё нет.

Если найдена ошибка, обработчик ставит фокус на первое поле и возвращается. Если ошибок нет, `emit('save', student)` передаёт объект родителю. HTTP внутри этой функции отсутствует. В родительском `@save="save"` слева имя события, справа функция: их можно назвать по-разному.

Шаблон использует `v-model`, подписи `label`, ограничения required/pattern/min/max/maxlength и условные сообщения. `novalidate` отключает автоматическую проверку при обычной отправке браузера, но не явный вызов `checkValidity`. `.prevent` отменяет обычную отправку, чтобы работал наш сценарий. `fieldset` отключает все поля при `busy`, кнопка меняет текст. Scoped-стили ставят пары полей рядом и вертикально на узком экране.

```vue
import { computed, reactive, ref, watch } from 'vue'
import { validateStudent } from '../validation'

const props = defineProps({
  student: { type: Object, default: null },
  busy: { type: Boolean, default: false },
  backendFields: { type: Object, default: () => ({}) }
})
const emit = defineEmits(['save'])
const form = reactive({ name: '', group: '', isu: '', dormitory: '', room: '', term: '', international: false, note: '' })
const errors = ref({})
const submitted = ref(false)
const fieldErrors = computed(() => ({ ...props.backendFields, ...errors.value }))
const maxTerm = new Date().getFullYear() + '-12-31'

watch(() => props.student, (student) => {
  if (student) {
    for (const field of Object.keys(form)) form[field] = student[field] ?? ''
  }
}, { immediate: true })

function getStudentData() {
  return {
    name: form.name.trim().replace(/\s+/g, ' '),
    group: form.group.trim().toUpperCase(),
    isu: form.isu.trim(),
    dormitory: form.dormitory === '' ? null : Number(form.dormitory),
    room: form.room.trim(),
    term: form.term,
    international: form.international,
    note: form.note.trim()
  }
}

watch(form, () => {
  if (submitted.value) errors.value = validateStudent(getStudentData())
})

function submit(event) {
  if (props.busy) return
  submitted.value = true
  const student = getStudentData()
  form.name = student.name
  form.group = student.group
  errors.value = validateStudent(student)
  for (const element of event.currentTarget.elements) {
    if (element.name && !element.checkValidity() && !errors.value[element.name]) {
      errors.value[element.name] = element.validationMessage
    }
  }
  const firstError = Object.keys(errors.value)[0]
  if (firstError) {
    event.currentTarget.elements.namedItem(firstError)?.focus()
    return
  }
  emit('save', student)
}
```

## StudentEditPage.vue: сохранить студента через API

[StudentEditPage.vue](frontend/src/pages/StudentEditPage.vue) связывает форму с сетью. `route` читает адрес, `router` выполняет переходы. При наличии ID это редактирование; без ID создание. `student` хранит исходную запись, `loading` её чтение, `busy` сохранение, `error` общее сообщение, `fields` серверные ошибки. Контроллер отменяет запросы этого экземпляра страницы.

**`onMounted`.** Для создания сразу завершается. Для редактирования ждёт `getStudent(id, signal)` и записывает ответ в `student`. Ошибку показывает только при актуальной операции, а `finally` снимает загрузку. Шаблон показывает форму после успешного чтения; при неудачном GET пустая редактируемая форма не появляется. Здесь нет SSE-подписки: уведомления не перезаполняют ввод во время редактирования.

**`save(value)`.** Вызывается событием дочерней формы, аргумент — подготовленные поля. Проверяет повторный запуск, включает `busy`, очищает прежние ошибки. Затем ждёт `saveStudent(id, value, signal)`: API выбирает POST без ID и PUT с ID. Успешный ответ содержит сохранённого студента; по `saved.id` открывается карточка, если пользователь ещё не ушёл.

При ошибке отменённая операция игнорируется, иначе `failure.message` показывается целиком, `failure.fields` передаются форме. При 403 выполняется возврат на главную. `finally` снимает блокировку после любого результата. Например, занятый ИСУ проходит местную проверку формата, но сервер возвращает конфликт, и сообщение появляется у поля.

**`onUnmounted`.** Вызывает отмену контроллера. Это останавливает клиентское ожидание и предотвращает поздний переход, но не обещает откат уже завершённого изменения БД.

Шаблон передаёт форме данные, блокировку и ошибки, слушает `save`, показывает загрузку и ссылку назад. Scoped-стиль ограничивает ширину и центрирует страницу.

<details>
<summary>Полный код: frontend/src/pages/StudentEditPage.vue</summary>

```vue
<script setup>
import { onMounted, onUnmounted, ref } from 'vue'
import { useRoute, useRouter } from 'vue-router'
import { getStudent, saveStudent } from '../api'
import MessageBox from '../components/MessageBox.vue'
import StudentForm from '../components/StudentForm.vue'

const route = useRoute()
const router = useRouter()
const student = ref(null)
const loading = ref(Boolean(route.params.id))
const busy = ref(false)
const error = ref('')
const fields = ref({})
const controller = new AbortController()

onMounted(async () => {
  if (!route.params.id) return
  try {
    student.value = await getStudent(route.params.id, controller.signal)
  } catch (failure) {
    if (!controller.signal.aborted) error.value = failure.message
  } finally {
    loading.value = false
  }
})

onUnmounted(() => controller.abort())

async function save(value) {
  if (busy.value) return
  busy.value = true
  error.value = ''
  fields.value = {}
  try {
    const saved = await saveStudent(route.params.id, value, controller.signal)
    if (!controller.signal.aborted) await router.push('/students/' + saved.id)
  } catch (failure) {
    if (controller.signal.aborted) return
    error.value = failure.message
    fields.value = failure.fields || {}
    if (failure.status === 403) await router.replace('/')
  } finally {
    busy.value = false
  }
}
</script>

<template>
  <section class="page form-page">
    <RouterLink to="/" class="button">Назад к списку</RouterLink>
    <MessageBox :text="error" />
    <p v-if="loading">Загрузка студента...</p>
    <StudentForm v-else-if="!route.params.id || student" :student="student" :busy="busy" :backend-fields="fields" @save="save" />
  </section>
</template>

<style scoped>
.form-page {
  max-width: 65rem;
  margin: 0 auto;
}
</style>
```

## StudentPage.vue: карточка с живым обновлением

[StudentPage.vue](frontend/src/pages/StudentPage.vue) получает ID из адреса, хранит студента и отражает чтение, удаление и ошибки. Контроллер `controller` относится к удалению, `loadController` к текущему чтению. Отдельная переменная `stopEvents` отключает уведомления.

**`load()`.** Вызывается при открытии и нужном серверном событии. Аргументов нет: ID берётся из маршрута. Отменяет предыдущее чтение, создаёт свежий контроллер и сохраняет его одновременно в локальном `current` и общем `loadController`. Локальная ссылка позволяет конкретной операции проверить именно свою отмену. Затем включает загрузку, очищает ошибку и ждёт GET. Только актуальная операция может записать ответ.

При ошибке актуальное чтение показывает сообщение; при 404 дополнительно обнуляет `student`, убирая сведения об удалённой записи. В `finally` только актуальная операция снимает загрузку, чтобы старый ответ не помешал новому. Значимого возвращаемого значения у `load` нет: результатом становится состояние карточки.

**`onMounted`.** Запускает `load` и `watchStudents`. Событие с ID вызывает повторное чтение только при совпадении с текущим студентом; `undefined` означает общее уведомление готовности и тоже требует загрузки. Изменения чужих записей карточке не нужны.

**`remove()`.** Вызывается кнопкой без аргумента: выбранный студент уже находится в состоянии. Проверяет повторный вызов и подтверждение, включает удаление, вызывает DELETE, после успеха открывает список. Ошибку показывает при актуальной операции; `finally` снимает флаг удаления.

**`onUnmounted`.** Отменяет удаление, активное чтение и закрывает SSE. Поэтому старая карточка перестаёт получать события.

Шаблон показывает пары названий и значений через dl/dt/dd только после появления студента. Дата форматируется прямо выражением, пустая заметка получает запасной текст, действия доступны администратору. Во время повторного чтения прежние сведения могут оставаться видимыми. Scoped-стили создают двухколоночную карточку, широкую заметку с переносами; на телефоне остаётся одна колонка.

## Общая связь: кто хранит пользователя, кто делает запросы

Эта часть посвящена входу, состоянию пользователя и выбору доступных экранов. Нужно понимать ее границу с работой со студентами. Страница студентов читает `auth.isAdmin`, а сетевой запрос проходит общую обработку сессии. Pinia хранит доступные интерфейсу сведения о пользователе. `session.js` организует вход, выход и получение профиля. `api.js` отправляет HTTP и обновляет токены. Окончательное разрешение читать или изменять данные проверяет Java-сервер.

Под состоянием понимаем текущие данные приложения. Локальное состояние принадлежит экземпляру компонента: например, текст пароля в форме. Глобальное доступно разным компонентам: текущий пользователь нужен одновременно шапке, маршрутам и страницам.

## main.js: создать приложение и подключить возможности

Это точка начала клиентского приложения. Импорты получают функции Vue и Pinia, корневой компонент App, Router и функции работы с сессией. Импорт CSS подключает общие стили.

`createApp(App)` создаёт приложение, затем подключается Pinia и только потом Router. Порядок полезен: при начальном переходе Router вызывает проверку пользователя, а проверка уже может обращаться к Pinia. `app.use` устанавливает такую возможность в приложение. `app.mount('#app')` связывает приложение с HTML-элементом, имеющим `id="app"`: внутри него Vue показывает интерфейс.

`onSessionExpired` передаёт API-модулю обработчик окончательно истёкшей сессии. Позднее, когда API вызовет этот обработчик, `clearSession` очистит клиентское состояние, а Router заменит текущий адрес на `/login?expired=1`. Параметр нужен для сообщения пользователю. `replace` заменяет запись истории вместо добавления новой.

```js
app.mount('#app')
```

## stores/auth.js: общее хранилище Pinia

`defineStore('auth', ...)` описывает хранилище; `useAuthStore()` получает его действующий экземпляр. Разные компоненты читают одно общее состояние.

`user` сначала равен `null`: сведения о пользователе ещё не получены. `checked=false` отдельно означает, что начальная проверка не выполнена. `error` временно переносит ошибку проверки на страницу входа. Getter `isAdmin` вычисляет признак роли: существует ли пользователь с `role === 'ADMIN'`. Оператор `?.` позволяет безопасно прочитать роль при `user=null`.

Action `setUser(user)` вызывается менеджером сессии: сохраняет переданный объект либо `null`, отмечает проверку выполненной и очищает ошибку. `clear()` вызывает `setUser(null)`. Поэтому после очистки `checked` становится **true**, а не false: приложение уже знает, что считает пользователя невошедшим. Хранилище не отправляет HTTP и не хранит JWT. Скрытие кнопки по `isAdmin` управляет интерфейсом, не серверными правами.

<details>
<summary>Полный код: frontend/src/stores/auth.js</summary>

```js
import { defineStore } from 'pinia'

export const useAuthStore = defineStore('auth', {
  state: () => ({
    user: null,
    checked: false,
    error: ''
  }),
  getters: {
    isAdmin: state => state.user?.role === 'ADMIN'
  },
  actions: {
    setUser(user) {
      this.user = user
      this.checked = true
      this.error = ''
    },
    clear() {
      this.setUser(null)
    }
  }
})
```

</details>

## session.js: действия со входом и защитой от поздних ответов

Модуль связывает общий HTTP-клиент и хранилище. Его функции вызывают Router, формы, профиль и корневая кнопка выхода.

`userVersion` — счётчик актуальности операций с пользователем. Перед ожиданием ответа сохраняется текущая версия. Если за время ожидания произошёл вход или выход и версия изменилась, старые сведения нельзя записать поверх нового состояния. Например, запрос профиля начался до выхода, а вернулся после: пользователь не должен появиться снова.

`clearSession()` увеличивает этот счётчик, сбрасывает состояние API через `resetSession` и очищает Pinia. Она используется при окончательной потере сессии и завершении выхода. Сама функция не удаляет HttpOnly cookies: это делает сервер соответствующим ответом.

`loadUser(force=false)` получает текущего пользователя. Router обычно вызывает её без аргумента. Если проверка уже выполнена и принудительная загрузка не нужна, функция сразу возвращает `auth.user`. Иначе запрашивает `GET /api/auth/me`. В ответе приходят сведения профиля, которые сохраняются только при прежней `userVersion`.

Параметр `notifyExpired:false` отключает для этого запроса общий обработчик перенаправления: результат отсутствия входа здесь обрабатывает сама функция. Механизм обновления токенов HTTP-клиентом при этом остаётся доступен. Если запрос окончательно получает 401, `clearSession` фиксирует отсутствие входа. Другие ошибки передаются вызывающему коду. Ошибка устаревшей операции не должна сбросить нового пользователя. Итоговый результат функции — актуальное `auth.user`.

`loginUser(username, password)` вызывается формой входа. Она начинает новую версию, сбрасывает состояние API и отправляет POST с учётными данными. Опция `auth:false` исключает попытку обновить прежнюю авторизацию ради самого входа. После успеха сбрасывается сохранённый CSRF и, если операция актуальна, принудительно загружается профиль. Функция подготавливает состояние приложения, а не возвращает JWT в страницу.

`registerUser(user)` отправляет username, email и password на регистрацию и сбрасывает сохранённый CSRF. Регистрация не вызывает вход автоматически; страницу входа затем открывает компонент формы.

`logoutUser()` сразу делает прежние загрузки профиля устаревшими, ждёт серверный выход через `logoutSession` и после успеха вызывает `clearSession`. При ошибке ожидания очистка дальше не выполняется, исключение получает App и показывает сообщение.

Важно различать три вещи. `checked` — известен ли результат проверки пользователя. `userVersion` — актуальны ли ответы операций получения пользователя. `sessionVersion` внутри API — актуальны ли сетевые запросы для обработки 401, обновления и завершения сессии. Это разные задачи; ни один счётчик не является токеном или серверным доказательством роли.

<details>
<summary>Полный код: frontend/src/session.js</summary>

```js
import { request, resetCsrf, resetSession, logoutSession } from './api'
import { useAuthStore } from './stores/auth'

let userVersion = 0

export function clearSession() {
  userVersion++
  resetSession()
  useAuthStore().clear()
}

export async function loadUser(force = false) {
  const auth = useAuthStore()
  if (auth.checked && !force) return auth.user
  const version = userVersion
  try {
    const user = await request('GET', '/api/auth/me', undefined, { notifyExpired: false })
    if (version === userVersion) auth.setUser(user)
  } catch (error) {
    if (version !== userVersion) return auth.user
    if (error.status !== 401) throw error
    clearSession()
  }
  return auth.user
}

export async function loginUser(username, password) {
  const version = ++userVersion
  resetSession()
  await request('POST', '/api/auth/login', { username, password }, { auth: false })
  resetCsrf()
  if (version === userVersion) await loadUser(true)
}

export async function registerUser(user) {
  await request('POST', '/api/auth/register', user, { auth: false })
  resetCsrf()
}

export async function logoutUser() {
  userVersion++
  await logoutSession()
  clearSession()
}
```

</details>

## router.js: адрес выбирает компонент

`createRouter` получает список маршрутов, `createWebHistory` использует обычные адреса без обязательного `#`. Запись маршрута связывает `path` с компонентом. `:id` обозначает изменяемый участок: карточки разных студентов используют один компонент.

Корневой `/` показывает список. `/students/new` и `/students/:id/edit` выбирают форму, `/students/:id` — карточку. Отдельно объявлены вход, регистрация и профиль. Последний маршрут перехватывает всё неизвестное и выбирает NotFoundPage. `meta` содержит наши дополнительные настройки: необходимость входа, роль администратора и заголовок.

`beforeEach(async to => ...)` — обработчик перед переходом. Router передаёт в `to` целевой маршрут. Сначала загружаются либо берутся уже проверенные сведения пользователя. Ошибка сохраняется для формы входа; если целевой экран защищён, возвращается `/login`.

Дальше последовательно проверяются условия. Нет пользователя у защищённого маршрута — переход на вход. Экран административный, а роль обычная — на `/`. Вошедший пользователь открывает вход или регистрацию — тоже на `/`. Возврат адреса меняет направление перехода. Если проверки пройдены, устанавливается заголовок вкладки. Метаданные сами ничего не запрещают: правила реализует этот обработчик.

Это клиентская организация навигации. Злоумышленник может обойти интерфейс и отправить HTTP отдельно, поэтому роли ещё раз проверяет Spring Security. Адрес страницы карточки и адрес запроса данных API также различаются.

<details>
<summary>Полный код: frontend/src/router.js</summary>

```js
import { createRouter, createWebHistory } from 'vue-router'
import { useAuthStore } from './stores/auth'
import { loadUser } from './session'
import StudentsPage from './pages/StudentsPage.vue'
import StudentPage from './pages/StudentPage.vue'
import StudentEditPage from './pages/StudentEditPage.vue'
import LoginPage from './pages/LoginPage.vue'
import RegisterPage from './pages/RegisterPage.vue'
import ProfilePage from './pages/ProfilePage.vue'
import NotFoundPage from './pages/NotFoundPage.vue'

const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/', component: StudentsPage, meta: { auth: true, title: 'Студенты' } },
    { path: '/students/new', component: StudentEditPage, meta: { auth: true, admin: true, title: 'Добавление студента' } },
    { path: '/students/:id/edit', component: StudentEditPage, meta: { auth: true, admin: true, title: 'Редактирование студента' } },
    { path: '/students/:id', component: StudentPage, meta: { auth: true, title: 'Карточка студента' } },
    { path: '/login', component: LoginPage, meta: { title: 'Вход' } },
    { path: '/register', component: RegisterPage, meta: { title: 'Регистрация' } },
    { path: '/profile', component: ProfilePage, meta: { auth: true, title: 'Профиль' } },
    { path: '/:pathMatch(.*)*', component: NotFoundPage, meta: { title: 'Страница не найдена' } }
  ]
})

router.beforeEach(async to => {
  const auth = useAuthStore()
  try {
    await loadUser()
  } catch (error) {
    auth.error = error.message
    if (to.meta.auth) {
      return '/login'
    }
  }
  if (to.meta.auth && !auth.user) {
    return '/login'
  }
  if (to.meta.admin && !auth.isAdmin) {
    return '/'
  }
  if (auth.user && ['/login', '/register'].includes(to.path)) {
    return '/'
  }
  document.title = to.meta.title + ' | Общежитие'
})

export default router
```

## App.vue: общая шапка, выход и выбранная страница

App остаётся общей оболочкой при переключении страниц. `auth` даёт сведения пользователя, `route` — текущий адрес и метаданные, `router` — возможность выполнить переход. Локальные `busy` и `error` относятся к кнопке выхода.

`logout()` вызывается нажатием этой кнопки. Повторное нажатие при busy игнорируется; затем сбрасывается ошибка, выполняется `logoutUser` и переход на вход. Ошибка становится сообщением, а `finally` снимает занятость при любом исходе.

В шаблоне заголовок берётся из метаданных с запасным текстом. Для вошедшего показаны список, профиль, имя, роль и выход; для остальных — вход и регистрация. MessageBox получает текст ошибки. До завершения первого сопоставления маршрута отображается загрузка, затем `RouterView` показывает выбранную страницу. Ключ `route.path` создаёт новый экземпляр при смене пути, в том числе между карточками разных ID.

Scoped-стили оформляют только эту оболочку: шапку и навигацию через flex, заголовок, отступы main. На узком экране отступы уменьшаются. Scoped означает, что сборка ограничивает соответствие селекторов этому компоненту; это обычное оформление браузера.

## LoginPage.vue: вход и защита от запоздалого перехода

`form` — reactive-объект username/password. `busy` блокирует повторную отправку, `error` хранит общее сообщение, `fields` — ошибки по именам полей. Начальная общая ошибка берётся из Pinia, после чего там очищается, чтобы не повторяться при каждом открытии.

`active` сообщает, существует ли этот экземпляр страницы. `onUnmounted` устанавливает false при уходе. Запрос может закончиться позднее: проверка active предотвращает неожиданный возврат на список после того, как пользователь уже ушёл. Это проверка актуальности перехода, а не отмена HTTP-запроса.

`submit()` вызывается отправкой формы. Она проверяет busy, очищает общее сообщение, запускает `validateLogin`. Если объект ошибок непустой, останавливается до HTTP. Иначе включает busy, вызывает `loginUser` с обрезанными крайними пробелами username и исходным паролем. Пароль намеренно не обрезается. При успехе активная страница открывает `/`; при ошибке показывает сообщение и серверные `fields`, затем снимает busy.

Шаблон показывает также сообщения по параметрам `expired` и `registered`. `@submit.prevent` отменяет стандартную перезагрузку формы; `v-model` связывает поля с состоянием. Disabled-fieldset блокирует поля на время запроса, кнопка меняет текст. HTML-атрибуты помогают вводу. Scoped-стиль ограничивает ширину формы и центрирует её.

<summary>Полный код: frontend/src/pages/LoginPage.vue</summary>

## RegisterPage.vue: создание обычного пользователя

Состояние устроено аналогично входу, но form содержит ещё email. `submit()` выполняет `validateRegister`, прекращает работу при ошибках и передаёт `registerUser` отдельный объект. Username и email очищаются от крайних пробелов, пароль передаётся без изменений. Поля выбора роли нет: роль USER определяет сервер.

После успешной регистрации активная страница открывает `/login?registered=1`: следующий экран показывает сообщение о завершении. `active` и `onUnmounted` защищают от позднего перехода после ухода. Ошибки сохраняются в error/fields, а finally возвращает форму в доступное состояние.

В шаблоне предусмотрены три поля, подсказки, ошибки и ссылка на вход. Используются как HTML-ограничения, так и общая JavaScript-проверка. `autocomplete` подсказывает браузеру назначение полей; значение new-password относится к создаваемому паролю. Scoped-стили задают ширину страницы и спокойное оформление подсказок.

## validation.js: общие проверки до отправки

Все три функции получают объект значений и возвращают объект ошибок вида «имя поля → сообщение». Пустой объект означает отсутствие обнаруженных ошибок. Они не делают HTTP и не изменяют базу. Окончательная проверка остаётся на сервере. Регулярное выражение здесь описывает допустимый формат строки, а `.test` проверяет соответствие.

`validateStudent(student)` вызывается формой студента после подготовки данных. Сначала обязательными объявлены name, group, isu, dormitory, room, term: пустая строка или null дают ошибку. Объект ожидается с полным набором свойств формы, включая строковую note.

- ФИО должно содержать минимум два слова из латинских или русских букв, включая Ё; внутри слов разрешены дефис и апостроф. Между словами ожидаются одиночные пробелы. Нормализация в форме заранее убирает лишние пробелы. Максимальная длина — 100.
- Группа: заглавная латинская буква, затем 3 или 4, затем цифра от 1 до 4 и ещё две цифры. Например, M3301 соответствует правилу.
- ИСУ: ровно шесть цифр, первая не ноль. Это строковый идентификатор.
- Общежитие: целое число от 1 до 8; отдельная проверка целочисленности исключает дробь.
- Комната соединяет этаж от 1 до 20 с двухзначным номером от 01 до 99; 1203 означает этаж 12, комнату 03.
- Для даты вычисляется последняя дата текущего года. Строка ограничивается диапазоном от 1970-01-01 до этой границы и проверяется на возможность разбора через Date.parse. Формат год-месяц-день позволяет сравнивать такие нормализованные строки по порядку. Строгую календарную корректность дополнительно проверяет backend.
- Заметка допускает до 2000 символов.

`validateLogin(user)` вызывается формой входа и используется регистрацией. После удаления крайних пробелов username обязателен и содержит 3–32 латинские буквы, цифры или подчёркивания. Пароль обязателен; допустимы 8–72 печатных ASCII-символа без пробела. Поэтому русский текст пароля этому правилу не соответствует.

`validateRegister(user)` сначала получает все ошибки validateLogin, затем добавляет проверку email. Упрощённое выражение требует части до и после @, точку в доменной части и отсутствие пробелов; также проверяется предел 254 символа. Это форматная проверка, не подтверждение существования ящика.

```js
export function validateStudent(student) {
  const errors = {}
  const required = ['name', 'group', 'isu', 'dormitory', 'room', 'term']
  for (const field of required) {
    if (student[field] === '' || student[field] === null) {
      errors[field] = 'Обязательное поле'
    }
  }
  if (student.name && !/^[A-Za-zА-Яа-яЁё]+(?:[-'][A-Za-zА-Яа-яЁё]+)*(?: [A-Za-zА-Яа-яЁё]+(?:[-'][A-Za-zА-Яа-яЁё]+)*)+$/.test(student.name)) {
    errors.name = 'Введите минимум фамилию и имя, используя буквы, дефис или апостроф внутри слов'
  }
  if (student.name.length > 100) {
    errors.name = 'ФИО должно быть не длиннее 100 символов'
  }
  if (student.group && !/^[A-Z][34][1-4][0-9]{2}$/.test(student.group)) {
    errors.group = 'Группа: латинская заглавная буква, 3 или 4 и еще три цифры, например M3301'
  }
  if (student.isu && !/^[1-9][0-9]{5}$/.test(student.isu)) {
    errors.isu = 'ИСУ должен состоять из 6 цифр, первая не 0'
  }
  if (student.dormitory !== null && (!Number.isInteger(student.dormitory) || student.dormitory < 1 || student.dormitory > 8)) {
    errors.dormitory = 'Номер общежития от 1 до 8'
  }
  if (student.room && !/^(?:[1-9]|1[0-9]|20)(?:0[1-9]|[1-9][0-9])$/.test(student.room)) {
    errors.room = 'Комната: этаж от 1 до 20 и номер от 01 до 99, например 1203'
  }
  const maxTerm = new Date().getFullYear() + '-12-31'
  if (student.term && (student.term < '1970-01-01' || student.term > maxTerm || Number.isNaN(Date.parse(student.term)))) {
    errors.term = 'Дата заселения от 1970-01-01 до ' + maxTerm
  }
  if (student.note.length > 2000) {
    errors.note = 'Заметки не длиннее 2000 символов'
  }
  return errors
}

export function validateLogin(user) {
  const errors = {}
  if (!user.username.trim()) errors.username = 'Введите имя пользователя'
  else if (!/^[A-Za-z0-9_]{3,32}$/.test(user.username.trim())) {
    errors.username = 'Имя пользователя: от 3 до 32 латинских букв, цифр или знаков _'
  }
  if (!user.password) errors.password = 'Введите пароль'
  else if (!/^[!-~]{8,72}$/.test(user.password)) {
    errors.password = 'Пароль: от 8 до 72 латинских букв, цифр или знаков, без пробелов'
  }
  return errors
}

export function validateRegister(user) {
  const errors = validateLogin(user)
  if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(user.email.trim()) || user.email.trim().length > 254) {
    errors.email = 'Введите почту в формате name@example.com, не длиннее 254 символов'
  }
  return errors
}
```

## Как ручной SQL обновляет Vue у других пользователей

Серверу нужно заметить изменение, даже если его выполнили напрямую в PostgreSQL, минуя Java API. Поэтому сигнал начинается в базе: SQL-триггер вызывает `pg_notify`, Java получает уведомление и передает его открытым страницам через SSE. SSE — поток HTTP-сообщений от сервера браузеру. Клиент получает только ID и перечитывает данные обычным запросом, используя существующие фильтры и проверки доступа.

### StudentEvents.java

Это один объект Spring для всего приложения. В нем хранятся настройки подключения, список клиентов, поток-получатель и признак продолжения работы. `volatile` делает изменения общих полей видимыми между потоками. `CopyOnWriteArrayList` позволяет безопасно обходить список, пока другие потоки добавляют и удаляют клиентов.

- **Конструктор** получает URL, имя и пароль базы из настроек Spring и сохраняет их. Это серверные параметры; клиентам они не передаются.
- **`start()`** вызывается Spring после создания объекта благодаря `@PostConstruct`. Создает один Java-поток, который выполняет `listen`. Это отдельный получатель уведомлений, работающий независимо от CRUD-запросов.
- **`subscribe()`** вызывается из `StudentController.events()` при GET `/api/requests/events`. Создает ответ `SseEmitter` на 30 секунд, добавляет клиента и отправляет `ready`. Обработчики завершения, ошибки и таймаута убирают клиента из списка; таймаут также завершает ответ.
- **`listen()`** открывает отдельное соединение с PostgreSQL, включает autocommit и выполняет `LISTEN student_changes`. Через `PGConnection` ожидает уведомления и передает их в `broadcast`. При SQL-ошибке повторяет подключение через секунду. `getNotifications(1000)` ждет максимум секунду, но просыпается при поступлении сообщения: это не обязательная секундная задержка обновления.
- **`broadcast(event, data)`** обходит подключенных клиентов и вызывает `send` для каждого. После восстановления связи с базой рассылает `ready`, чтобы страницы перечитали изменения, пропущенные за время разрыва.
- **`send(client, event, data)`** записывает именованное SSE-событие конкретному клиенту. При ошибке записи убирает этого клиента. Уведомления об изменениях отправляет поток слушателя после получения NOTIFY; первоначальный ready отправляется при подписке клиента. Рассылка изменений не входит в транзакцию сохранения студента.
- **`stop()`** вызывается при остановке Spring благодаря `@PreDestroy`. Снимает `running`, прерывает поток, закрывает соединение и SSE-ответы, очищает список и ограниченно ждет завершения потока.

Событие `ready` имеет пустые данные и означает перечитывание состояния. `students-changed` несет строковый ID. После 30 секунд фронтенд перепроверяет сессию и подключается снова; это ограничивает срок работы соединения без повторной проверки авторизации.

<details>
<summary>Полный код: backend/src/main/java/ru/itmo/students/service/StudentEvents.java</summary>

```java
package ru.itmo.students.service;

import jakarta.annotation.PostConstruct;
import jakarta.annotation.PreDestroy;
import org.postgresql.PGConnection;
import org.postgresql.PGNotification;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Service;
import org.springframework.web.servlet.mvc.method.annotation.SseEmitter;

import java.io.IOException;
import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.SQLException;
import java.sql.Statement;
import java.util.List;
import java.util.concurrent.CopyOnWriteArrayList;

@Service
public class StudentEvents {

    private static final Logger log = LoggerFactory.getLogger(StudentEvents.class);

    private final String url;
    private final String username;
    private final String password;
    private final List<SseEmitter> clients = new CopyOnWriteArrayList<>();
    private volatile boolean running = true;
    private volatile Connection connection;
    private Thread listener;

    public StudentEvents(@Value("${spring.datasource.url}") String url,
                         @Value("${spring.datasource.username}") String username,
                         @Value("${spring.datasource.password}") String password) {
        this.url = url;
        this.username = username;
        this.password = password;
    }

    @PostConstruct
    public void start() {
        listener = new Thread(this::listen, "student-events");
        listener.setDaemon(true);
        listener.start();
    }

    @PreDestroy
    public void stop() {
        running = false;
        listener.interrupt();
        Connection current = connection;
        if (current != null) {
            try {
                current.close();
            } catch (SQLException e) {
                log.warn("Не удалось закрыть соединение уведомлений", e);
            }
        }
        for (SseEmitter client : clients) client.complete();
        clients.clear();
        try {
            listener.join(2000);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }

    public SseEmitter subscribe() {
        SseEmitter client = new SseEmitter(30_000L);
        client.onCompletion(() -> clients.remove(client));
        client.onTimeout(() -> {
            clients.remove(client);
            client.complete();
        });
        client.onError(error -> clients.remove(client));
        clients.add(client);
        send(client, "ready", "");
        return client;
    }

    private void listen() {
        while (running) {
            try (Connection current = DriverManager.getConnection(url, username, password)) {
                connection = current;
                if (!running) return;
                current.setAutoCommit(true);
                try (Statement statement = current.createStatement()) {
                    statement.execute("LISTEN student_changes");
                }
                PGConnection postgres = current.unwrap(PGConnection.class);
                broadcast("ready", "");
                while (running) {
                    PGNotification[] notifications = postgres.getNotifications(1000);
                    if (notifications == null) continue;
                    for (PGNotification notification : notifications) {
                        broadcast("students-changed", notification.getParameter());
                    }
                }
            } catch (SQLException e) {
                if (running) log.warn("Не удалось получить уведомления PostgreSQL", e);
            } finally {
                connection = null;
            }
            if (!running) break;
            try {
                Thread.sleep(1000);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                break;
            }
        }
    }

    private void broadcast(String event, String data) {
        for (SseEmitter client : clients) send(client, event, data);
    }

    private void send(SseEmitter client, String event, String data) {
        try {
            client.send(SseEmitter.event().name(event).data(data));
        } catch (IOException | IllegalStateException e) {
            clients.remove(client);
        }
    }
}
```

### V4__notify_student_changes.sql

Триггер — действие, автоматически выполняемое базой при изменении таблицы. `students_changed` вызывает функцию после INSERT, UPDATE или DELETE для каждой затронутой строки. При удалении берется `OLD.id`, при добавлении и изменении — `NEW.id`. Функция отправляет ID через канал `student_changes`. PostgreSQL доставляет уведомления после успешного COMMIT; ROLLBACK отменяет и изменения, и уведомления. Поэтому механизм одинаково охватывает API и ручной SQL.

<details>
<summary>Полный код: backend/src/main/resources/db/migration/V4__notify_student_changes.sql</summary>

```sql
create function notify_student_changes() returns trigger
language plpgsql as $$
begin
    if TG_OP = 'DELETE' then
        perform pg_notify('student_changes', OLD.id::text);
    else
        perform pg_notify('student_changes', NEW.id::text);
    end if;
    return null;
end;
$$;

create trigger students_changed
after insert or update or delete on students
for each row execute function notify_student_changes();
```

```nginx
        proxy_pass http://backend:8080;
        proxy_set_header Host $http_host;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

</details>


## Файлы сборки: что достаточно объяснить

`frontend/index.html` содержит пустой контейнер `#app` и подключение main.js. Vue монтирует туда приложение. Это входной HTML-документ SPA; карточки студентов не являются отдельными HTML-файлами.

`frontend/package.json` перечисляет зависимости: Vue, Vue Router, Pinia и RxJS; инструменты сборки — Vite и плагин Vue. `npm run build` вызывает vite build. Файл package-lock.json фиксирует конкретные версии дерева зависимостей, чтобы npm ci воспроизводимо их установил.

`frontend/vite.config.js` подключает обработку .vue. Его server.proxy относится к режиму разработки Vite: запросы /api передаются указанному backend. В Docker собранные файлы раздает Nginx, и там работает nginx.conf.

Frontend Dockerfile сначала собирает dist в Node-контейнере, затем копирует результат в образ Nginx. Backend Dockerfile собирает JAR через Gradle и запускает его в Java runtime. Compose объединяет frontend, backend и db; в сети контейнеров backend обращается к db по имени сервиса. Браузер использует адрес Nginx на localhost:8080.

В build.gradle PostgreSQL-драйвер доступен при компиляции, потому что StudentEvents использует PGConnection. Маска генерации jOOQ выбирает миграции создания таблиц; новую PL/pgSQL-функцию не должен разбирать этот генератор. Flyway выполняет все миграции, включая V4, при запуске приложения.

Метод StudentController.events() принимает GET /api/requests/events и возвращает результат events.subscribe() с типом ответа text/event-stream. Контроллер не выполняет рассылку самостоятельно. Узкий обработчик AsyncRequestNotUsableException в GlobalExceptionHandler учитывает закрытое клиентом соединение: туда не надо пытаться отправлять JSON ошибки сервера.

## Десять вопросов, на которые важно ответить своими словами

Сначала восстанови цепочку, затем открой ответ. Здесь проверяется смысл, а не дословное запоминание кода.

<details>
<summary>Что делает request и почему одной функции fetch недостаточно для нашего поведения?</summary>

Fetch отправляет запрос. Request дополнительно организует один refresh после 401, повтор операции, чтение ответа, общие ошибки и уведомление об истечении сессии. Подготовку CSRF и JSON выполняет вызываемый им send. Без общей функции эти действия пришлось бы согласованно повторять в страницах.

</details>

<details>
<summary>Почему HTTP 404 не обязательно попадает в catch сразу после fetch?</summary>

Fetch обычно успешно возвращает Response и при ошибочном HTTP-статусе. В нашей программе readResponse проверяет ok и выбрасывает Error со status. Сетевой отказ и ответ сервера с ошибкой — разные случаи.

</details>

<details>
<summary>Для чего version проверяется повторно после await refreshSession?</summary>

Пока ожидали сеть, пользователь мог выйти или начать другую сессию. Предыдущая проверка больше не гарантирует актуальность. Номер версии позволяет не повторять устаревший запрос и не очистить новую сессию из-за старого 401.

</details>

<details>
<summary>Что произойдет, если два запроса одновременно получили 401?</summary>

Оба ожидают общую refreshPromise. Один обмен обновляет cookies; каждый исходный запрос затем отдельно проверяет свою актуальность и отмену и может повториться один раз. Это особенно нужно при замене использованного refresh-токена.

</details>

<details>
<summary>Зачем указывать return await readResponse внутри try?</summary>

Чтобы асинхронное отклонение при чтении и проверке ответа было обработано текущим catch. Просто вернуть Promise означало бы передать его дальнейший результат вызывающему коду без этого локального ожидания.

</details>

<details>
<summary>Где начинается трехсекундная задержка и что ее сбрасывает?</summary>

StudentFilters сообщает новые поля, StudentsPage вызывает load(3000), changes передает условия и delay. Внешний switchMap отменяет предыдущую работу и создает новый timer. Новое изменение запускает отсчет заново. Начальная загрузка и смена страницы используют ноль.

</details>

<details>
<summary>Почему switchMap действительно отменяет HTTP именно в этой реализации?</summary>

Он отписывается от старого Observable. В loadStudents предусмотрена функция очистки: controller.abort(). Сигнал передан в fetch через API. Без такой связи отписка сама по себе не гарантировала бы остановку сетевого запроса.

</details>

<details>
<summary>Почему изменение таблицы через psql становится видно в другой вкладке?</summary>

Триггер отправляет NOTIFY после commit. Поток Java получает его через LISTEN и отправляет событие SSE. Страница перечитывает API, записывает результат в ref, Vue обновляет DOM. Каждый этап выполняет свою часть работы.

</details>

<details>
<summary>Что делает StudentForm при успешной проверке и кто выполняет POST или PUT?</summary>

Форма отправляет событие save с подготовленным объектом. StudentEditPage получает его в save(value), вызывает saveStudent и открывает карточку после ответа. API выбирает POST без id и PUT с id. В форме нет собственного HTTP-сохранения.

</details>

<details>
<summary>Чем отличаются Pinia, cookies и серверная проверка роли?</summary>

Pinia хранит состояние интерфейса, включая имя и роль. Cookies передают токены браузером; HttpOnly не позволяет странице прочитать их через document.cookie. Сервер проверяет токен и право операции независимо от видимости кнопок и значений Pinia. Пароль БД и секрет подписи JWT клиенту вообще не передаются.

</details>
