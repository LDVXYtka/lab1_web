# Проверка API

Выбери окружение `local`. На вкладке Secrets задай `adminPassword` из корневого `.env` и придумай `userPassword` для тестового пользователя. Пароль пользователя: 8–72 латинских букв, цифр или знаков без пробелов.

В настройках Bruno должны быть включены сохранение и отправка cookie. Запускай запросы последовательно по порядку папок. Первый запрос получает CSRF-токен, остальные передают его в заголовке `X-XSRF-TOKEN`. Токены входа сервер сохраняет в HttpOnly cookie, JSON с токенами больше нет.

Регистрация создает нового тестового пользователя с ролью USER. Вторая папка входит как ADMIN, проверяет операции со студентом, включая QUERY с JSON-фильтрами, и удаляет созданного студента.

Третья папка сначала входит как ADMIN и создает отдельного студента для проверки ролей. Затем USER читает его и получает 403 при попытках создания и удаления. В конце ADMIN удаляет тестовую запись и выходит. Проверки используют выданный сервером ID, а не запись с ID 1, поэтому работают и в пустой базе.

После выхода первая папка повторно отправляет сохраненный прежний refresh-токен и ожидает 401. Это проверяет отзыв токена на сервере, затем копия удаляется из cookie-хранилища Bruno.

Перед отдельным запуском запросов сначала выполни `CSRF` и нужный вход. Для запросов с `studentId` сначала выполни создание студента во второй папке. Для `roleStudentId` выполни начало третьей папки: вход ADMIN и создание студента для ролей. После проверки выполни удаление и выход в конце той же папки.
