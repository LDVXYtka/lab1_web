# Объяснение лабораторной работы

Приложение хранит список студентов, проживающих в общежитии. Можно добавить студента, открыть его досье, изменить данные и удалить запись. Данные сохраняются в браузере через localStorage.

## 1. Как запустить

Открой папку проекта в VS Code. Нажми правой кнопкой мыши на `table.html` и выбери `Open with Live Server`. Начальная страница приложения - `table.html`.

На первом запуске список пустой, если по ключу `lab1Students` еще нет данных. После добавления студента обнови страницу: запись должна остаться.

localStorage относится к адресу сайта: важны протокол, имя хоста и порт. Например, `http://localhost:5500` и `http://127.0.0.1:5500` используют разные хранилища. Для повторного открытия работы используй прежний адрес Live Server и тот же профиль браузера.

## 2. За что отвечает каждый файл

| Файл | Назначение |
| --- | --- |
| `table.html` | Список студентов и подтверждение удаления |
| `form.html` | Общая форма для добавления и редактирования |
| `person.html` | Досье одного студента |
| `styles.css` | Оформление всех трех страниц и адаптивность |
| `storage.js` | Чтение, запись, общие сообщения и отображение даты |
| `table.js` | Построение таблицы и удаление студента |
| `form.js` | Проверка полей, заполнение формы и сохранение |
| `person.js` | Поиск студента по ИСУ и вывод его досье |
| `favicon.ico` | Котик на вкладке браузера |

HTML описывает элементы страницы, CSS задает их вид, JavaScript добавляет действия. Каждая страница подключает общий `storage.js` и свой файл логики. Здесь обычные отдельные скрипты, без классов, сборщика и `import/export`.

У скриптов указан атрибут `defer`: браузер выполняет их после разбора HTML, сохраняя порядок подключения. Поэтому элементы страницы уже доступны, а общие функции из `storage.js` определены до запуска файла конкретной страницы.

`id` в HTML обозначает конкретный элемент страницы. Например, `id="student-form"` нужен, чтобы JavaScript нашел форму. Это идентификатор HTML-элемента, а не дополнительный идентификатор студента.

## 3. Как устроена запись студента

Объект объединяет связанные данные: у каждого свойства есть имя и значение. Пример одного студента:

```js
const student = {
    name: "Иванов Иван",
    group: "P3220",
    isu: "123456",
    dorm: 2,
    room: "1001",
    term: "2026-09-01",
    international: false,
    note: "Нужен второй комплект ключей"
};
```

`name` - ФИО, `group` - группа, `isu` - ИСУ, `dorm` - общежитие, `room` - комната, `term` - дата начала заселения, `international` - признак иностранца, `note` - заметки.

ИСУ является единственным идентификатором записи. Отдельное техническое свойство `id` не создается. ИСУ хранится строкой: это обозначение студента, с которым не нужны арифметические действия. Номер комнаты тоже хранится строкой, а номер общежития переводится в число через `Number(...)`.

Все студенты находятся в массиве. Массив - упорядоченный набор значений. Здесь каждое значение массива является объектом студента. Пустой список обозначается `[]`.

Признак иностранца имеет логический тип: `true` означает "Да", `false` означает "Нет". У снятой галочки есть корректное значение `false`; заставлять пользователя ставить ее нельзя.

## 4. Общие функции в storage.js

`storageKey` содержит строку `"lab1Students"`. По этому ключу приложение находит свой список в localStorage.

`showMessage(text, isError = false)` находит блок `#message`, записывает сообщение через `textContent` и выбирает класс сообщения. При пустом тексте блок скрывается. Если второй аргумент равен `true`, сообщение оформляется как ошибка. Это блок на странице; `alert()` не используется.

`loadStudents()` читает сохраненную строку методом `localStorage.getItem(storageKey)`. Когда ключ отсутствует, `getItem` возвращает `null`, а функция возвращает пустой массив: это нормальный первый запуск.

Если строка есть, `JSON.parse(saved)` восстанавливает массив из текста. Функция проверяет, что результат является массивом и у его записей есть строковые `isu` и `name`. Это базовая проверка структуры, не повтор всех правил формы.

`try/catch` позволяет обработать ошибку чтения или разбора JSON. При ошибке появляется сообщение, а функция возвращает `null`. Здесь `[]` означает корректный пустой список, а `null` означает, что прочитать список не удалось. Эти случаи специально различаются.

`saveStudents(students)` преобразует массив в строку через `JSON.stringify(students)` и записывает ее методом `localStorage.setItem(storageKey, ...)`. При успехе возвращается `true`, при ошибке - `false` и сообщение на странице.

Если чтение не удалось, интерфейс не заменяет поврежденные данные пустым списком. При ошибке сохранения форма не закрывается, а удаление не завершается в интерфейсе. Приложение не показывает успешный результат до успешной записи.

`formatDate(date)` преобразует `2026-09-01` в `01.09.2026`. `split("-")` разбивает строку на части, `reverse()` меняет их порядок, `join(".")` соединяет точки между частями. В хранилище остается исходный формат `ГГГГ-ММ-ДД`.

## 5. Список и удаление в table.js

В начале файл находит элементы таблицы через `document.querySelector(...)`. Аргумент `"#students-body"` означает поиск элемента с `id="students-body"`. Найденные элементы сохраняются в переменные, чтобы обращаться к ним дальше.

`renderStudents(students)` строит таблицу из массива. Сначала `replaceChildren()` очищает прежние строки. Затем обновляется количество студентов и видимость сообщения о пустом списке.

Внешний цикл `for...of` перебирает студентов. Для каждого создается строка `tr`. Массив `values` содержит значения семи столбцов, а внутренний цикл создает для каждого значения ячейку `td`. Метод `append(...)` добавляет созданный элемент внутрь другого элемента.

Последняя ячейка содержит ссылки "Подробнее", "Изменить" и кнопку "Удалить". Ссылки включают ИСУ, например `person.html?isu=123456`. `encodeURIComponent` безопасно подготавливает значение для помещения в адрес.

`addEventListener("click", function () { ... })` связывает кнопку с функцией, которая выполнится после нажатия. Сразу при построении строки эта функция не выполняется.

Кнопка "Удалить" записывает ИСУ выбранного студента в `isuToDelete`, показывает подтверждение на странице и переводит фокус на "Отмена". Сам список в этот момент еще не меняется.

Обработчик `#cancel-delete` скрывает подтверждение, сбрасывает `isuToDelete` в `null` и возвращает фокус к области таблицы.

Обработчик `#confirm-delete` заново читает список и получает новый массив через `filter(...)`. Условие `student.isu !== isuToDelete` оставляет всех студентов, кроме выбранного. При успешном сохранении таблица перестраивается, подтверждение скрывается и появляется сообщение об удалении.

В конце файла список читается и передается в `renderStudents`. Если чтение завершилось ошибкой, страница показывает ошибку, а не сообщение о корректном пустом списке.

## 6. Добавление и редактирование в form.js

`fieldNames` содержит имена семи полей, проверяемых как текст, число или дата. Цикл заполняет объект `fields` ссылками на HTML-поля. Например, `fields.group` позволяет обратиться к полю группы. Галочка обрабатывается отдельно через свойство `.checked`.

`new URLSearchParams(window.location.search)` разбирает часть адреса после `?`. В адресе `form.html?isu=123456` вызов `parameters.get("isu")` вернет строку `"123456"`. Без такого параметра он вернет `null`.

`editingIsu` хранит найденный параметр. Если он равен `null`, создается новый студент. Если параметр есть, приложение ищет существующего студента для редактирования. Параметр в адресе не создает нового человека автоматически.

`lastDate` получает последний день текущего года по часам устройства: `new Date().getFullYear() + "-12-31"`. Это значение присваивается `max` поля даты. Например, в 2026 году верхняя граница равна `2026-12-31`.

`normalizeName(name)` убирает пробелы по краям через `trim()` и заменяет последовательности пробельных символов одним пробелом через `replace(/\s+/g, " ")`. Например, `"  Иванов   Иван  "` превращается в `"Иванов Иван"`.

`getFieldError(name)` проверяет одно поле и возвращает текст ошибки. Пустая строка означает, что ошибки нет. Сначала проверяется встроенное состояние поля `validity`: некорректный числовой ввод и отсутствие обязательного значения. Затем выполняются правила конкретного поля.

`checkField(name)` вызывает `getFieldError`, помещает результат в блок под полем, скрывает пустую ошибку и меняет `aria-invalid`. Значение `aria-invalid="true"` сообщает вспомогательным технологиям, что поле ошибочно. Возвращаемое логическое значение удобно использовать при общей проверке формы.

`fillForm(student)` записывает свойства студента в `.value` соответствующих полей. Для галочки используется `.checked`, поскольку она хранит состояние выбора. Функция также меняет заголовок, название кнопки и делает поле ИСУ `readOnly`.

`readOnly` разрешает видеть и выделять значение, но запрещает обычное редактирование. Дополнительно JavaScript сравнивает введенный ИСУ с `editingIsu`. Случайное изменение атрибута через инструменты разработчика поэтому не становится разрешением менять идентификатор.

При открытии режима редактирования `find(...)` ищет запись с нужным ИСУ. Если запись отсутствует, форма скрывается и появляется сообщение. Если хранилище не прочиталось, форма тоже скрывается, чтобы нельзя было записать поверх неизвестных данных новый список.

### Когда появляются ошибки

Переменная `submitted` сначала равна `false`. Пока пользователь не пытался сохранить форму, ошибки под полями не показываются.

Обработчик `blur` у ФИО срабатывает при выходе из поля и нормализует пробелы. Если попытка сохранения уже была, он также обновляет ошибку ФИО.

Обработчик `input` срабатывает при изменении значения пользователем. Группа сразу переводится в верхний регистр через `toUpperCase()`. После первой попытки сохранения этот обработчик повторно проверяет изменяемое поле. Поэтому исправленная ошибка исчезает по мере ввода.

### Что происходит после нажатия "Сохранить"

1. Событие `submit` вызывает обработчик формы. `event.preventDefault()` отменяет стандартную отправку и перезагрузку страницы.
2. `submitted` становится `true`, прежнее общее сообщение очищается, список заново читается из localStorage.
3. ФИО и некоторые строковые значения нормализуются, группа переводится в верхний регистр.
4. Цикл вызывает `checkField` для каждого проверяемого поля. Запоминается первое ошибочное поле.
5. Если ошибка есть, на первое ошибочное поле переводится фокус. Обработчик завершается без записи.
6. Если ошибок нет, из текущих значений создается объект `student`.
7. При добавлении `push(student)` помещает его в конец массива. При редактировании `findIndex(...)` находит индекс прежней записи, после чего `students[index] = student` заменяет ее.
8. Если запись успели удалить, редактирование останавливается с сообщением. Если сохранение массива прошло успешно, `window.location.href = "table.html"` открывает список.

Кнопка или ссылка отмены просто возвращает к таблице. Предупреждения о несохраненных изменениях нет, как и автоматического сохранения черновика.

## 7. Правила валидации

Валидация - проверка соответствия введенных значений установленным правилам. Она применяется до записи студента.

| Поле | Правило |
| --- | --- |
| ФИО | Минимум два слова; русские или латинские буквы; дефисы и апострофы внутри слов; до 100 символов после нормализации |
| Группа | Одна латинская буква и четыре цифры; буква становится заглавной |
| ИСУ | Шесть цифр, первая от 1 до 9; уникальность; запрет изменения при редактировании |
| Общежитие | Одно целое число от 1 до 8 |
| Комната | Три или четыре цифры; этаж от 1 до 20; последние две цифры от 01 до 99 |
| Начало заселения | От 01.01.1970 до 31 декабря текущего года включительно |
| Иностранец | Галочка; и установленное, и снятое состояние допустимы |
| Заметки | Необязательный текст до 2000 символов, включая переносы строк |

Например, `101` означает этаж 1 и комнату 01, `1001` означает этаж 10 и комнату 01, `2099` означает этаж 20 и комнату 99. Значения `100`, `1000` и `2000` запрещены, потому что комнаты 00 нет. `2101` запрещено из-за этажа 21.

ФИО проверяется по формату, а не по реестру людей. Два слова из разрешенных букв не доказывают, что человек существует. Одинаковые ФИО разрешены: различать студентов нужно по ИСУ.

Проверка уникальности использует `some(...)`, который возвращает `true`, если хотя бы один элемент подходит под условие. Условие ищет совпадающий ИСУ и исключает собственную запись редактируемого студента. Иначе сохранение любых изменений блокировалось бы совпадением с собой.

Уникальность действует в списке этого приложения в текущем хранилище браузера. Это не проверка ИСУ в университетской системе.

Заметки допускают обычный текст, специальные символы и эмодзи. JavaScript считает длину строки в единицах UTF-16, поэтому некоторые эмодзи занимают две или больше единиц. Заметки не обрезаются через `trim()`: введенные пробелы и переносы сохраняются.

### Как читать регулярные выражения

Регулярное выражение - шаблон для проверки строки. Метод `.test(value)` возвращает `true`, если значение подходит.

- `^` - начало строки, `$` - конец. Вместе они требуют соответствия всей строки.
- `[A-Z]` - одна заглавная латинская буква.
- `[0-9]` - одна цифра, `[1-9]` - одна цифра без нуля.
- `{4}` и `{5}` - ровно четыре или пять повторений предыдущей части.
- `+` - одно или больше повторений, `*` - ноль или больше.
- `|` - выбор между вариантами, `(?:...)` - объединение части шаблона в группу.

Для группы используется `/^[A-Z][0-9]{4}$/`: сначала буква, затем ровно четыре цифры. Для ИСУ используется `/^[1-9][0-9]{5}$/`: первая цифра ненулевая, затем еще пять цифр.

Шаблон комнаты состоит из двух частей. `(?:[1-9]|1[0-9]|20)` допускает этажи 1-9, 10-19 или 20. `(?:0[1-9]|[1-9][0-9])` допускает комнаты 01-09 или 10-99. Обе части должны присутствовать подряд.

В шаблоне ФИО сначала идет слово из разрешенных букв. Внутри слова могут повторяться дефис или апостроф с буквами после него. Затем обязательна хотя бы еще одна такая часть через пробел. Поэтому одиночное имя и дефис на конце слова не подходят.

Дата из поля `type="date"` поступает в формате `ГГГГ-ММ-ДД`. У такого фиксированного формата порядок строк совпадает с порядком дат. Поэтому код сравнивает значение с `"1970-01-01"` и `lastDate` как строки. Само поле даты также проверяется через `validity`.

### Зачем нужны и HTML, и JavaScript

Атрибут `required` обозначает обязательное поле, `pattern` задает шаблон текстового поля, `min` и `max` - допустимые границы, `maxlength` - максимальную длину текста. Браузер вычисляет состояние `field.validity` по этим ограничениям.

У формы есть `novalidate`. Он отключает автоматическую остановку отправки с браузерными подсказками, чтобы ошибки можно было единообразно показать под полями. Ограничения HTML и объект `validity` при этом продолжают работать; обработчик JavaScript читает их сам.

Одного HTML недостаточно для уникальности ИСУ: для нее нужен список других студентов. JavaScript также нормализует значения, проверяет неизменность ИСУ и выводит понятные сообщения. `novalidate` не означает, что форма сохраняет все без проверки.

## 8. Досье в person.js

Файл читает ИСУ из адреса, загружает массив и ищет нужного студента через `find`. Найденные свойства помещаются в элементы страницы: например, `#number` получает ИСУ, а `#date` - отформатированную дату заселения.

Логическое значение иностранца преобразуется в "Да" или "Нет". Если заметки являются пустой строкой, показывается "Заметок нет.". Ссылка редактирования получает тот же ИСУ в адресе формы.

Если ИСУ не передан или запись отсутствует, досье и ссылка редактирования скрываются. Пользователь получает сообщение и может вернуться к списку. Если проблема возникла при чтении хранилища, сохраняется сообщение об этой проблеме.

Данные пользователя выводятся через `textContent`. Этот способ вставляет именно текст, не превращая его в HTML. Например, заметка `<b>текст</b>` должна отображаться вместе с угловыми скобками и тегами. Ввод пользователя не вставляется через `innerHTML`.

## 9. Оформление и размеры окна

Все страницы используют один файл стилей и бело-серое оформление. CSS-классы объединяют элементы с одинаковой ролью: поля формы, кнопки, сообщения и действия в строках.

Форма на широком экране располагает короткие поля в двух колонках благодаря `display: grid` и `grid-template-columns: repeat(2, minmax(0, 1fr))`. При ширине до 600 пикселей правило `@media` меняет сетку на одну колонку. ФИО и заметки занимают полную ширину области формы.

Таблица имеет минимальную ширину 1120 пикселей и находится в отдельном контейнере с `overflow: auto`. Максимальная высота контейнера равна `65vh`, то есть 65% высоты окна, а на узком экране - `60vh`. Если строк много, появляется вертикальная прокрутка. Если столбцы не помещаются, появляется горизонтальная. Ползунки появляются, когда содержимое действительно превышает доступный размер.

Заголовки таблицы используют `position: sticky` и `top: 0`, поэтому остаются вверху при вертикальной прокрутке. Таблица сохраняет столбцы на телефоне и прокручивается внутри своей области. Основная страница, форма и навигация подстраиваются под ширину экрана. Тег `meta` с `name="viewport"` задает соответствие ширины страницы ширине устройства.

Для заметок `white-space: pre-wrap` сохраняет пробелы и переносы строк, а `overflow-wrap: anywhere` позволяет переносить длинный текст. Общее `box-sizing: border-box` включает рамки и внутренние отступы в заданную ширину элементов.

## 11. Короткие ответы для защиты

1. **Что такое HTML и какие элементы здесь используются?** HTML описывает структуру документа. В работе есть заголовки, ссылки, форма с полями, таблица и блоки сообщений. Элементы выбираются по назначению: для перехода используется ссылка, для действия - кнопка.
2. **Как устроена HTML-страница и что такое DOM?** `<!DOCTYPE html>` включает стандартный режим обработки документа. Внутри `html` находятся `head` с метаданными и подключениями файлов и `body` с содержимым страницы. DOM - представление документа в виде объектов. Через `document.querySelector` я нахожу элемент и меняю его содержимое, свойства или дочерние элементы.
3. **Как работает форма и ее проверка?** Поля имеют `label`, тип и ограничения HTML. Обработчик `submit` отменяет стандартную отправку, проверяет значения и сохраняет их только при отсутствии ошибок. Проверки отображаются рядом с полями.
4. **Как подключен CSS и как выбираются стили?** Все страницы подключают один `styles.css`. Селектор указывает, к каким элементам применить правило: например, `.field` выбирает элементы с классом `field`. Для обычных правил в этом файле более специфичный селектор имеет приоритет: селектор по id сильнее селектора класса, а селектор класса сильнее селектора тега. При равной специфичности выигрывает более позднее правило. Объявление с `!important` имеет приоритет над обычными объявлениями той же категории; здесь оно нужно у `[hidden]`, чтобы скрытый блок не показывался из-за другого правила `display`.
5. **Как реализована адаптивность?** При уменьшении ширины меняется расположение полей и других элементов. Форма переходит с двух колонок на одну. Таблица имеет собственный контейнер с горизонтальной и вертикальной прокруткой.
6. **Где выполняется JavaScript этой работы?** В браузере пользователя. Здесь нет серверного приложения. JavaScript обрабатывает события, работает с DOM и сохраняет данные локально через Web Storage API.
7. **Какие типы данных, функции, объекты и массивы используются?** ФИО и ИСУ являются строками, общежитие - числом, галочка - логическим значением. Студент представлен объектом, список - массивом. Функции группируют повторяемые действия, например чтение хранилища и проверку поля.
8. **Что такое событие и обработчик?** Событие сообщает о действии, например нажатии кнопки или вводе. Через `addEventListener` я назначаю функцию, которая выполнится при этом событии. В работе используются `click`, `input`, `blur` и `submit`.
9. **Как JavaScript меняет страницу?** Создает строки и ячейки через `createElement`, добавляет их через `append`, меняет текст через `textContent`, значения полей через `.value` и состояние галочки через `.checked`. Свойство `hidden` скрывает ненужные блоки.
10. **Чем отличаются localStorage, cookies и IndexedDB?** localStorage хранит строковые пары ключ-значение в браузере между обычными запусками и не добавляет их автоматически к сетевым запросам. Cookies - небольшие значения, которые браузер может отправлять серверу с подходящими запросами; у них настраиваются область действия и срок хранения. IndexedDB позволяет асинхронно работать со структурированными записями и индексами. По моему варианту список хранится в localStorage. Дополнительно существует sessionStorage: оно хранит строковые значения в рамках сеанса вкладки.
11. **Зачем нужен JSON?** localStorage принимает строки, а список студентов является массивом объектов. `JSON.stringify` превращает его в строку, `JSON.parse` восстанавливает структуру при чтении. JSON не содержит функции приложения.
12. **Что такое CRUD и где он здесь?** Create - добавление через форму, Read - таблица и досье, Update - редактирование существующей записи, Delete - удаление после подтверждения. Для поиска нужной записи используется ИСУ.
13. **Почему такая структура файлов?** Есть три отдельные страницы с разными задачами и один общий файл стилей. Каждая страница имеет небольшой файл своей логики. Общие операции с хранилищем вынесены в `storage.js`, чтобы не копировать их три раза.
14. **Зачем разделять структуру, оформление и поведение?** HTML отвечает за содержимое, CSS за внешний вид, JS за действия. Например, изменение цвета не требует менять сохранение данных, а изменение правил ИСУ не требует перестраивать таблицу в HTML.
15. **Как использовать DevTools для проверки?** Во вкладке `Elements` можно проверить DOM и стили, в `Console` - ошибки JavaScript, в `Application` - localStorage. Режим устройства помогает проверять узкую ширину. Вкладка `Network` позволяет увидеть загрузку HTML, CSS, JS и favicon.
